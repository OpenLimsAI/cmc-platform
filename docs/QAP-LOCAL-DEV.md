## 启动

端口固定为后端8040、前端5140，被占用时检查所属服务，不终止其他项目或自动换端口。依赖已在本机安装，后端锁定于 `backend/uv.lock`。

```sh
# 在 backend 目录
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8040
```

```sh
# 在 frontend 目录
pnpm dev --host 127.0.0.1
```

放行页访问 `http://127.0.0.1:5140/qap/release`；导入预览入口为 `/qap/imports`。前端 `/qap/api` 与 `/qap/health` 代理到8040；`/mdm` 代理到本机MDM应用18000，并把刷新Cookie的路径改为 `/mdm/api/v1/auth`。通过本机 Hub 验收时使用 `http://127.0.0.1:5100/qap/`。

当前 `.env` 已按负责人确认更新两个角色列表，未更换数据库账号或注入 MDM 密钥。分析连接的只读设置不能替代数据库最小权限账号；真实员工/预览联调前需分配角色并安全配置验签材料。不要把真实密钥、令牌、原始Excel或备份提交Git。

稳定性页访问 `http://127.0.0.1:5140/qap/stability`。先选项目，再选择样品、检验类别、产线/组别及批号；上游条件变化会清除下游旧选择。每个检测项按方法、样品、类别和单位分开展示，初始显示4组条件，后续可继续展开；原始明细全部返回、表格分页，不把观察数当独立批次数。数据读取使用 `POST /qap/api/v1/analysis/stability/options` 和 `POST /qap/api/v1/analysis/stability`，没有数据库写操作。

两页首次进入都展开筛选，选择项目后可在结果区点击“生成图表”（筛选区原“分析”按钮也保留）；小窗口生成后自动定位结果。若仍见旧版顶部筛选，请刷新旧标签页。没有选择项目不会自动查询全部项目，也不代表本地无数据。稳定性只有单时间点时显示散点并提示原因。

## RD / QC 数据来源

放行与稳定性筛选区第一项可选 `RD_LIMS（研发）` 或 `QC_LIMS（历史记录）`；先选来源，再选项目并生成图表。QC 当前读取本机旧共享 staging，尚不包含旧 Excel；质量属性保留原名，组合尚未匹配时可手动选择或留空。切换来源清除旧项目、条件和结果。QC 不套 RD 规格，完整数据范围及权限待办见 [来源接入记录](QAP-DATA-SOURCES-001.md)。

## 身份配置

配置键见 `backend/.env.example`。`QAP_ENVIRONMENT=development`、`QAP_AUTH_REQUIRED=false` 且完全没有验签配置时，仅允许旧只读开发；结构预览仍拒绝。一旦提供验签配置，就要求有效身份及浏览白名单。`production`/`test` 或显式要求认证时，缺失/无效验签配置导致启动失败。最终部署必须显式设为 `production` 并启用认证。

MDM 是唯一登录源，QAP 不签发令牌，也不保存密码。HS256 需与 MDM 一致的共享验签材料，RS256 使用 MDM RSA 公钥文件。角色通过 `QAP_READ_ROLES`、`QAP_IMPORT_PREVIEW_ROLES` 两个JSON数组配置。2026-09-16已按负责人确认设置默认值：浏览为 `["QAP_QC_GENERAL","QAP_QA_RELEASE"]`，预览为 `["QAP_QC_GENERAL"]`；显式空数组仍关闭授权。SYS_ADMIN等其他角色不自动获得本平台权限，中文显示名不能代替MDM角色码。

QC综合可查看并导入Excel（正式导入功能待完成，当前只做结构预览）；QA放行在本模块仅查看，不授予放行审批或任何导入/修改权限。两个角色已在Mac MDM创建，尚未分配员工；项目/部门范围仍待确认。具体登记及最终部署复现步骤见 [角色登记](QAP-ROLE-SETUP-20260916.md)。

`GET /api/v1/auth/status` 只公开配置/认证状态；`GET /api/v1/auth/me` 返回验签后的身份和能力。无效令牌401仅尝试续期一次；无角色和临时密码均403，不进入续期循环。前端复用 cmab-hub 的统一会话模块，原值复制；令牌共用统一存储，支持跨标签退出。预览期间重新核验身份会隐藏内容，同一已验证身份续期保留所选文件，换人或撤权销毁旧状态。

## 结构预览契约

| 接口 | 当前作用 |
|---|---|
| `GET /api/v1/imports/capabilities` | 返回当前允许的草案模板与限制 |
| `GET /api/v1/imports/templates/qap_long_preview_v1.xlsx` | 下载仅含表头及说明的合成空模板 |
| `POST /api/v1/imports/preview` | multipart只接受 `file` 与 `template_code`，验证身份/角色后才读取请求体 |

上述接口均要求预览权限。默认新增 `qap_first_table_v1`，按现有项目第一表十个维度与5/6/7行布局读取，保留指标原名及中文标题。真实15个完整工作簿已可生成预览，仍有待核对的源表问题，不能宣称已可完成导入；现状与修正见 [第一表兼容结论](QAP-FIRST-TABLE-COMPATIBILITY-20260916.md)。

此前模板 `qap_long_preview_v1` 版本1，工作表“质量数据”，第一行为 `project_code,batch_number,attribute,value,unit`。五个表头必须存在，数据行的batch_number/attribute/value必填。project_code只是来源引用，不表示已经匹配MDM；空unit不表示无量纲。此模板用于验证结构，**尚未批准为正式业务导入模板**。

单文件10MiB、请求体额外64KiB封装开销，解压内容128MiB、1000个ZIP条目；目标数据页50000行、256个有效数据列、200000个有效单元格、3000000个XML单元格。纯格式格不计入有效单元格预算，完整目标页流式扫描以确定实际有值范围，随后仅解析此范围。按实际接收字节限制，不信任Content-Length或Excel维度声明。每个应用进程同时解析一个文件，忙时429；解析循环有60秒协作式超时（不是独立进程强制终止）；多进程总内存、进程隔离的硬超时及网关请求限制仍是开放正式导入前的待办。

解析服务在内存中工作；HTTP multipart 解析可能使用自动关闭的临时缓冲文件，**没有永久原文件归档、历史登记或业务写入**。返回原值/格式/坐标、文件hash、问题、可信操作人；页面最多展示200行、1000条问题，并标明总数与截断。结构状态依据完整解析结果，不只依据展示切片。公式不执行、百分数不换算；未实现规格/单位/批准判断。`can_commit=false` 和 `business_validation=pending` 固定，没有提交端点。

公开 `/health` 只表示服务在线；分析数据库检查改为受浏览守卫保护的 `/api/v1/meta/database-health`，不会返回连接信息或业务表计数。

## 测试复现

```sh
# backend 目录：全部使用合成身份/内存文件和替代仓储，无业务库写入
.venv/bin/python -m pytest -q
```

```sh
# frontend 目录
pnpm test:auth
node --test tests/releaseDraft.test.mjs
pnpm build
```

浏览器回归在5140启动前端后运行 `node tests/importPreview.browser.mjs` 和 `node tests/release.browser.mjs`，需要本机Playwright及Chrome。可用 `QAP_PLAYWRIGHT_MODULE` 指向现有Playwright包路径，`QAP_BROWSER_CHANNEL` 指定已有浏览器渠道；不需要下载业务样本。脚本启动独立临时浏览器配置，拦截所有身份/业务接口为合成响应并阻止非本机请求。它验证页面与接口契约，真实XLSX解析/上传边界由后端测试覆盖，不能冒称真实MDM/数据库端到端验收。

稳定性浏览器回归为 `node tests/stability.browser.mjs`，采用同样的本机合成数据边界；覆盖四种视图、缺单位限制、保留原数值、来源明细、迟到请求、异常重试和手机图表尺寸。

统计旧回归测试通过仍不能证明混合模型组名排序风险或质量业务口径已验证；必须后续独立验收。
