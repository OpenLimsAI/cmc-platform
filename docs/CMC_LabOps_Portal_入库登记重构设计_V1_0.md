# CMC LabOps Portal — 入库登记重构设计 V1.0

> 状态：设计稿（需求已确认，待评审后进入编码）
> 范围：合并「入库登记」与「批量入库」为单一入口;表单常驻;无编码勾选;批量=数量按位置分配
> 关联：`CMC_LabOps_Portal_存放位置管理增强设计_V1_0.md`（位置树/-80 孔位/散放批量的后端基础）

---

## 1. 背景与目标

现状两个痛点：
1. 入库登记每个类型标签下**只有一个编码查询框**,必须"先查编码→再显示批次表单",多一步、不直观。
2. 「批量入库」是独立菜单/页面;但批量本质就是入库的一种**数量分配**方式,不该单列。

目标：把入库收敛成**一个**「入库登记」页,表单常驻、按类型联动,并把"批量"表达为**数量在多个位置上的分配**。

### 1.1 已确认的需求决策

| # | 决策 |
|---|------|
| D1 | 删除独立「批量入库」菜单/页面,全部并入「入库登记」 |
| D2 | 入库页**直接显示完整表单**(通用 + 类型专属),取消"先查询再显示" |
| D3 | 类型标签(试剂/耗材/标准品/色谱柱)联动下方**类型专属字段** |
| D4 | 物料编码框旁加**「无编码」勾选框**;编码即时解析,不再有独立查询步骤 |
| D5 | 合并页内含**两种模式**:「单物料」详细登记 + 「多物料批量」多行表格(多物料能力保留) |
| D6 | 批量=数量按位置分配,两场景:A 参比品孔位起始填充、B 同批物料多散放位置 |
| D7 | -80 起始填充规则:**从起始孔起连续 N 个孔必须全空,中间有占用即报错** |

---

## 2. 总体形态：单页 + 两模式

菜单仅保留 **入库登记**(`/intake`);页内顶部一个模式切换:

```
入库登记
 ├─ [单物料]  ← 默认。详细表单,支持 A/B 位置分配
 └─ [多物料批量]  ← 多行表格,一次录入多个不同物料(沿用现 BulkIntakePage)
```

菜单移除「批量入库」(`/intake-bulk` 路由与菜单项删除;原 BulkIntakePage 作为"多物料批量"模式内嵌)。

---

## 3. 模式一：单物料登记(详细表单)

### 3.1 类型标签 + 专属字段(常驻)
- 顶部四标签:**试剂 / 耗材 / 标准品 / 色谱柱**(卡片式 + 彩色类型横幅,沿用现有)。
- 切换标签 → 下方"类型专属信息"分区联动:
  - 标准品 → 浓度、消光系数
  - 色谱柱 → 序列号、资产编号、负责人
  - 试剂 / 耗材 → 无专属字段(显示占位说明)
- **整张表单进入即显示**,不再需要先解析物料。

### 3.2 物料识别:编码即时解析 + 无编码勾选
- 一行:`物料编码 [输入框]  ☐ 无编码`
- **未勾选(编码模式)**:
  - 输入编码,**失焦/回车即时解析**(本地查→MDM 取);旁边显示解析到的**物料名称**(绿色确认)。
  - 没查到 → 行内提示 + "去 MDM 登记此物料"按钮(沿用现有跳转)。
  - 解析结果仅作展示与取 `material_id`;表单其它部分始终可见可填。
- **勾选无编码**:
  - 编码框禁用;旁边出现 **物料名称(必填)** + **单位(必填)**,可选 规格 / 厂家 / 级别。
  - 名称用 AutoComplete,可复用已建过的无编码物料(避免重复建);否则提交时按保留码 `TT内部物料`、`data_source=local` 新建本地物料。

### 3.3 通用批次字段
- 批号(必填)、有效期、入库日期(默认今天)。
- 备注。

### 3.4 存放与数量分配(核心)
入库方式由**所选存放位置的性质**决定:

**(a) 散放单一位置(默认)** — 选一个柜板层/普通冰箱隔板 + 数量 N → 该位置一条批次 + IN。

**(b) 散放多位置分散(场景 B)** — 同一物料/批号,一个柜或板层放不下 → "**+ 加位置**":
  每行 `存放位置(级联) + 该位置数量`,可加多行,合计为总入库量。
  提交按"全有或全无":每行各自 find/建批次 + 一条 IN(复用后端 `POST /api/intake/bulk`,行的 `material_id/batch_no` 相同、`location_id` 不同)。

**(c) -80℃ 孔位(场景 A 起始填充)** — 选到 -80 冰箱时切到孔位分配,三种取位方式:
  - **起始填充(主推)**:选**起始孔**(架→层→盒→孔) + 数量 N → 系统沿地址顺序取**从起始孔起连续 N 个孔**;
    **要求这 N 个连续孔全部为空**,中间任一已占用则**报错并指出冲突孔**(D7)。
  - **自动分配**:系统找下一组 N 个空孔(沿用现有 free-cells)。
  - **手动选孔**:盒内热力图点选(沿用现有)。
  - 落库:N 条 `cell_occupancy` + 一条 IN(qty=N),地址串如 `TT3 B3:A,23`(沿用)。

> 说明:散放位置无"位置内顺序",故"起始往后填充"仅适用于 -80 等可寻址孔位;散放只走 (a)/(b)。

### 3.5 提交
- 散放(a/b)→ `POST /api/intake/bulk`(单行或多行)。
- -80(c)→ `POST /api/storage/occupy`(手动/自动,显式孔 id)或 `POST /api/storage/occupy-from`(起始连续,见 §5)。
- 无编码先建本地物料拿到 `material_id`,再走上述入库。

---

## 4. 模式二:多物料批量(多行表格)

- 沿用现 `BulkIntakePage`:共性 `入库类型 + 入库日期`;多行,每行 `物料(搜索选择) / 批号 / 有效期 / 数量 / 存放位置(散放级联)`。
- 适合一次收一批**不同物料**(如到货一箱杂项试剂)。
- 仅散放;**全有或全无**提交(复用 `POST /api/intake/bulk`)。
- 不在此模式做 -80 孔位(孔位个体化场景归"单物料"的场景 A)。

## 5. 后端接口

| 用途 | 接口 | 状态 |
|------|------|------|
| 散放入库(单行/多行;含单物料多位置 与 多物料批量) | `POST /api/intake/bulk` | **已有,复用** |
| -80 占用(显式孔 id:手动/自动) | `POST /api/storage/occupy` | **已有,复用** |
| -80 找空孔(自动分配) | `GET /api/storage/free-cells` | **已有,复用** |
| -80 **起始连续填充** | `POST /api/storage/occupy-from` | **新增** |
| 物料即时解析 / 本地建料 | `GET /api/materials`、`POST /api/materials`、`/from-mdm` | **已有,复用** |

### 5.1 新增 `POST /api/storage/occupy-from`（场景 A 起始连续）
入参:`start_cell_node_id` + `count` + 批次共性字段(material_id/batch_no/expiry/received_date/intake_type/…) + 可选 `sample_labels`。
逻辑(`crud.occupy_from_start`):
1. 校验 `start_cell_node_id` 为 CELL,取其所属 -80 冰箱。
2. 取该冰箱全部孔位按**地址顺序**(架 path → 盒 path → 孔号)排列,定位起始孔下标。
3. 取从起始孔起的 `count` 个孔;不足 `count` → 报错"从起始位置往后不足 N 个孔"。
4. **校验这 N 个孔全部为空**;任一已占用 → 报错并列出冲突孔地址(D7)。
5. 复用 `occupy_cells` 落 N 条 `cell_occupancy` + 一条 IN;返回 `{batch_id, count, addresses}`。
- 权限:`require_warehouse`;审计 `storage.occupy_from`。

## 6. 影响面

**前端**
- `modules/intake/pages/IntakePage.tsx`:重构为"两模式"容器;单物料模式实现 §3(常驻表单、即时解析、无编码勾选、位置分配 a/b/c)。
- `BulkIntakePage.tsx`:作为"多物料批量"模式内嵌(或并入 IntakePage)。
- `LocationPicker` / `FreezerCellPicker`:增加"起始孔 + 数量"取位方式;散放增加"加位置行"。
- `App.tsx` / `MainLayout.tsx`:删除 `/intake-bulk` 路由与"批量入库"菜单项。
- `api/storage.ts`:加 `occupyFrom`。

**后端**
- `routers/storage.py` + `crud.py`:新增 `occupy_from_start` 与路由;其余复用。
- 无数据库结构变更(storage_node / cell_occupancy / location 均已在)。

**非目标**
- 不改散放"批次+数量、实时聚合"的库存原则。
- 多物料批量不支持 -80 孔位(保持简单)。
- 不引入跨库主数据;无编码物料仍是 LabOps 本地物料。
