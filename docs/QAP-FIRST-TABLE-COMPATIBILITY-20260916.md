## “旧导入表”具体是什么

是本机 `cmc_analytics.quality.quality_data`，旧项目 quality_analysis_dashboard 使用的 Excel 结果表。不是临时表，也不表示要废弃或删除。

证据链：`config/fields.yaml` 定义前置维度；`analytics/data_loader.py` 第210行起按第5行英文表头、第6行中文表头、第7行数据读取；`analytics/transformers.py` 保留维度、把指标列拆成 attribute_name/value；`etl/import_service.py` 设置 QC_LIMS 来源，使用显式列清单写 quality.quality_data；`components/db_utils.py` 第186行起保留早期建表定义。中央已应用的一期迁移和本机 pg_catalog 结构与之对应。历史 quality_setup.sql 中旧库名/旧视图不是当前部署事实，不执行该脚本。

本机实际列：`id`、`data_source`、`data_type`、`project_id`、`production_line_id`、`group_id`、`sample_type`、`batch_number`、`sub_lot`、`test_type`、`placement_status`、`timepoint`、`timepoint_unit`、`sample_submission_date`、`attribute_name`、`value`、`source_file`、`update_time`。主键是 id（bigint），其余前置字段不是主键。旧代码中的 id_vars 是转换时保留的业务维度，不是唯一约束。

## 能否承接现有 Excel

| 对象 | 匹配结论 | 所需处理 |
|---|---|---|
| 现有 quality.quality_data | 前十列齐全；能承接按原规则解析后的数值长表 | 保留结构和历史数据；后续接只读兼容筛选，无须为了项目代码重建或更改主键 |
| 现有 LIMS staging 三表 | 不是这套 Excel 的目标；无 placement_status 等完整Excel语义 | 保留共享ETL边界；不能用QC历史staging项目/产线代替Excel字段 |
| 旧表 value double precision 与旧ETL数值清洗 | 不完整：定性/带限定符结果会被丢弃；无每格追溯、独立单位版本、员工及更正审计 | 正式模型保留原文/数值/限定符/格式/坐标/版本，不照搬旧清洗 |
| 新 QAP 五列结构预览 | 不匹配完整第一表，只是此前的技术草案 | 新增默认第一表契约，五列模板仅显式兼容保留 |
| 新 QAP 正式模型草案 | 原维度不够明确，放置状态缺显式字段 | 已修订DDM §5.2/5.3，十个Excel业务字段显式保留，归一化MDM码另存且不可代替原码；尚未建表 |

Excel 的一个业务行可有多个检测项，同一组维度可有复测/重复观察。不能用 project_id 或 batch_number 作结果主键，也不能因为十个维度相同就删除行。更正/防重必须结合文件hash、每格来源和明确的更正关系设计。

## 本轮代码修正

- 新默认模板 `qap_first_table_v1`：工作表“原始数据表”，英文第5行，中文第6行，数据第7行起；十个维度 field_name 与Excel英文表头一致，保留 project_id、group_id、production_line_id、placement_status 等原名。
- 按英文表头找字段，不按固定列序硬套；预览响应增加列位置、英文表头、中文表头、已识别字段。前端按实际列位置展示，不能因重名表头展示同一列值。
- 后续检测项列完整保留原名/原值/文本/公式缓存/格式/坐标；尚未批准的映射明确警告，不自动改名或转换百分比，也不丢弃“一致”“<LOD”等文本。
- 项目代码缺失、非文本、首尾空格明确报问题，不补零、不去前缀，不自动对应MDM项目。
- 两个模板均只预览、`can_commit=false`，鉴权仍为MDM QC综合角色。没有正式写库或新的匿名上传通道。
