# 状态判断规则

> 版本：V0.7｜日期：2026-10-10｜状态：已提交/push并部署Linux真实监控及Hub入口；服务、采集、权限和培训空表核验通过。真实MDM角色浏览器及下一次自然任务端到端通知待验收；详见 RELEASE_20261010。Mac保留模拟预览。

## 独立维度与来源

collection_status=ok/partial/unavailable/stale；run_status=success/partial_failed/failed/running/never_run/unknown；schedule_status=enabled/disabled/maintenance/unknown；health_status=healthy/warning/critical/unknown。保留源状态原文和所有reason_codes，不压成成功布尔值。

执行结果依同次同任务台账、完整终止日志、退出状态交叉核对；timer LastTrigger只证明触发。计划用systemd解析值/实际cron，etl_job声明不替代它。日志截断/权限不足/查询超时是证据缺失，不是无错误；来源冲突可见。

失联时当前health=unknown，旧成功不能维持绿色。最后已确认故障继续置顶，标“最后已知失败，当前未核实”，保留历史时间。每来源分别保存采集时间、证据时间、解析器/规则版本及范围。

## 状态解释（V1实现基线）

“正常”建议表示最近同一次任务完整结束、必要步骤均成功，且证据可读取并能对应本次执行。可以用程序日志作为依据，但要读明确的完成结论及失败汇总，而不是“程序启动了”“没有看到ERROR”或某一步SUCCESS。台账与结束日志都有时交叉核对；单一明确可靠结束记录能覆盖全流程时可用于该任务，不强求每个程序新增台账。缺失或冲突显示未知，零新增数据不自动算失败。

备份日志完成且应有产物确已生成，支持“备份执行完成”；已有hash或恢复验证另行显示范围，没有这类记录不能推导“可恢复”。卡片颜色对应最近观测的综合提示，具体映射在INFORMATION_ARCHITECTURE维护；执行状态和验证状态仍独立保存。

“漏跑”是到了计划时刻及宽限还没有启动；“运行超时”是已经启动，但运行耗时超过该任务的建议上限仍未完成。例如某个通常1分钟结束的ETL，15分钟后仍在运行，可显示“运行时间过长，请检查”。事后才看到已成功但耗时超过上限，显示“已完成，耗时偏长”，不改写为执行失败。只读看板不会因此停止、杀死或重跑程序。系统本身的硬超时终止与看板耗时提示分开记录。

“采集超时”是看板读取日志/数据库超过自己的等待预算，不等于ETL运行超时；这种情况显示当前状态未知。当前低频方案下，未结束的任务通常在07:00兜底或手动采集时被发现，不宣称到阈值即刻告警。

## 任务结束触发更新（Linux已接入；自然任务链路待验收）

主要更新方式改为事件触发：每个登记的ETL管道或备份批次结束后，platform-monitor自动执行一次只读采集。成功、失败、系统终止/超时都应有结束通知；不能只在成功分支通知。固定22:00不再作为主要更新方式，也不回到每分钟轮询。

父管道完整结束才通知：Lucullus六步骤、QC raw+staging、Vi-CELL/Nova raw+stage、仪器day/night批次各设备已结束或明确失败后分别通知。原任务失败不能因为通知成功被改为成功；监控故障也不能阻止、重试或改写原任务结果。

通知只说明“这个任务有新的执行结果可查”，不作为成功权威。采集器重新核对原台账、退出证据、日志/产物，保留Nova partial、质量警告、关联歧义。记录上次成功采集以来全部运行，不仅取latest；超出读取上限有界分页，无法覆盖明确标缺口。

同一时刻多个任务结束时建议2秒内合并一次全清单有界采集（实现参数草案），保留全部触发事件与各自运行身份；重复通知幂等。采集期间再有新事件须进入后续批次，不能丢掉或把它错误归为当前已采集。不能因合并而丢失失败后成功的两条历史。

### 兜底与未知状态

只靠结束事件不能发现根本未启动、永久卡住、通知链路中断或源记录被覆盖。用户已确认每天07:00（北京时间，Asia/Shanghai）执行一次全清单兜底检查，补查上次成功采集以来未覆盖的运行与计划窗口；collector已在Linux托管，边界测试通过；上线启动补查已执行，首次次日07:00自然兜底待观察。监控启动/重启补采及SYS_ADMIN手动更新已在Linux运行，并通过更新队列完成真实证据补查。这些均仅读运维证据，不重跑源任务或改变其调度。

07:00检查按各任务自己的计划与宽限判定：当天尚未到执行时刻的任务不算漏跑，仍在允许耗时内但尚未结束的任务以中性提示“本次尚未完成”呈现，不判失败，不设浅蓝或实时运行卡片状态；底层保留开始/未结束证据以判断超时。兜底本身未执行或读取失败须显示更新缺口/未知，不能保留绿色假正常。

在预期任务结束上限+宽限之后仍无有效更新，显示“更新逾期/当前未核实”，不能直接把没收到通知定为源任务失败；兜底/按需采集后才依据实际计划和启动记录确认漏跑/超时。明确采集失败立即unknown；事件队列不可用/积压必须可见。

2026-10-11修正：采集成功且已取得同一计划启动窗口内的明确结束记录，结束时间不晚于观测时间，则该次计划已被覆盖。即使任务提前完成、观测时间早于最长耗时截止，也保留已核实的绿色/黄色/红色，不要求截止后再通知一次；不能拿这份记录覆盖下一次计划、用窗口外手工执行替代计划，或豁免采集失败/未结束/未来结束证据。每日兜底以07:00作为必须取得观测的起点，07:05仅是等待期限；07:01完成的有效检查不会在07:05再被判过期，缺当日07:00之后观测仍未知。

普通任务正常结束后直到下一次预期运行，保留其截至时间，不按3分钟无新消息判失联。临时停用、手工/事件任务和外部未知计划分别处理。界面显示各源观测时间；截至时间之后未观测的执行不声称当前正常。

### 页面与读取预算

网页打开读最近快照，不持续自动刷新；需要最新状态时手动更新。事件后台采集无需用户开着页面。按需更新只调用固定范围采集器，并发合并，不接任意shell/路径/SQL。单来源5s、整轮30s为实现的只读预算，与查看频率无关。实际读取最多2个worker并行，排队不消耗单来源预算，避免Python启动竞争造成假超时。

表中的启动宽限/耗时上限是判定标准，不保证漏跑/卡住在该分钟数内就被发现；兜底模式可为事后发现。首次装载/维护单独记录规则版本及有效期，原任务调度和硬超时不因本设计调整。

## 计划时刻与父子关联

每计划时刻occurrence_key=(task_key,scheduled_for,rule_version)，记录时区、随机延迟、Persistent、activation_kind。时刻+宽限已过且所有必要启动证据可读仍无启动才确认missed_run；漏跑历史只从监控首次采集后生成，不以当前计划倒推上线前任务的漏跑。上线前真实来源记录仍可展示；早期调试观测中上线前推断的schedule引用保留原版本但不纳入有效历史。仅台账缺失且日志不可读为unknown+missing_evidence。

台账running超过阈值为running_timeout；服务已退出但台账未结束为orphaned_run/evidence_conflict，不猜结束、不写回台账。cron/QC缺父invocation_id时按有界时间窗关联，歧义必须展示；手工最新成功不自动匹配定时窗口。Persistent补跑注明catch_up，保留原漏跑历史，不推造多个成功。

父成功要求同次所有必需子步骤成功并有父终止证据：L01六步骤，L03十五raw+staging，L04/L05 raw+stage，L06/L07两设备。QC20:50独立stage不代表04:00整管道；两个归档班次不能用一个最新设备心跳互相替代。

批准停用需负责人、理由、有效期。无批准记录开关变化为unexpected_disabled；外部任务计划未知列unknown/未接入，不套每日漏跑。停用/维护与未接入不混同。

## 执行、质量和水位

Lucullus SUCCESS同时有VALIDATION，显示执行成功+质量warning；run1222的84条不是84次执行失败。Nova partial即使exit0也不得全绿，files_errored/rows_conflict/rows_unresolved单列；历史补齐文件warning保留范围，不推断为本次新增数据丢失。

zero_new_data不机械判失败。各水位语义分别为源业务时刻、抽取边界、文件mtime；updated_at也不总会推进。无需为监控额外访问Oracle或扫GMP raw。归档失败/延迟而下游成功零新增显示dependency_risk；归档与ETL是独立timer，固定20min不证明新输入已到位。

## 备份与恢复

分别显示execution、artifact、integrity、restore_verification；保留scope、artifact_ref、检查方法/版本/时间。文件存在/非空只证明生成产物，不能写“可恢复”。MDM当前每日integrity/restore均未验证；9-15发布hash/catalog只归那一份。

大小建议相对同任务最近7次成功中位数，<80%或>200%为warning，尚无大小基线时大小异常判定为unknown（不改写已核实的产物存在状态），不替代完整性。SHA/MD5报告只证明清单行范围；空清单为no_changed_files，不是full_verified。失败校验critical；缺记录区分not_verified（可读范围内没有已执行验证证据，不断言从未做过）和unknown（读不到）。第一版不重算大文件hash、不执行pg_restore --list/解压/恢复/厂商工具。

恢复记录须绑定产物、隔离目标、执行人/时间、抽检结果及实测耗时；仅SOP/计划为not_verified。本系统当前不设置GMP合规用RPO/RTO考核或演练审批。仅展示已有恢复/校验记录，缺记录注明未验证；不按文件大小推算恢复时间。没有已发现周期策略的库显示policy_missing/coverage_gap，严重度策略待确认；IT/VM/异地证据未取得为unknown。

### MDM逐份验证判定（P16已确认）

本节已实现并通过合成测试；Linux真实逐份验证执行及自然链路状态以RELEASE_20261011_BACKUP_VERIFY为准，此前每日未验证的旧记录仍保留。MDM验证器与只读monitor职责按ARCHITECTURE新增方案分离。

| 同次证据 | 建议呈现 |
|---|---|
| 备份失败 | 红色“备份失败”；不开始本次恢复验证，不借用旧验证 |
| 备份成功，验证待执行/执行中，未超预算 | 黄色“备份完成，验证尚未完成”；不新增浅蓝卡片 |
| 备份成功，同产物完整恢复通过，基线和必要范围检查均通过 | 绿色“备份完成，恢复验证通过”，详情标明验证范围和排除项 |
| 恢复错误、SHA失配或结构/计数对账失败 | 红色“备份完成，验证失败”；execution仍success，单独说明失败步骤 |
| 环境启动失败、资源不足、验证超时或未覆盖必要范围 | 黄色“备份完成，验证未完成”，不称文件损坏；保留失败原因 |
| 恢复通过但缺备份时点基线（如历史dump） | 黄色“恢复验证通过，完整性证据不足” |
| 当前报告不可读/解析错误/产物或运行关联不明确 | 灰色“验证结果未知”，保留已核实备份结果，不维持旧绿色 |
| 验证通过但临时资源清理失败 | 黄色“恢复验证通过，临时环境清理异常”，报告和资源缺口保留 |

证据须绑定task/host/environment、源运行引用、产物basename/字节数/SHA256及验证ID；时间窗仅作交叉核对，不能仅按latest JSON或mtime关联。integrity=verified要求可读取同快照基线且范围检查通过；restore=verified要求本产物实际完整恢复和约定检查通过。任一necessary范围缺口不得全绿；原执行证据与验证报告冲突必须显示。读取失败不推断备份失败，验证失败不改写备份退出码。

## 汇总与历史

首页置顶确认失败、漏跑/超时、采集异常、覆盖/验证缺口；无critical但仍有unknown或必要验证缺失，显示“未完全核实”。只有覆盖完整、证据新鲜及必要检查满足时才允许全部正常。顶层/子任务分别统计，10组不是10条子作业。

后续成功可标recovered，历史失败与原因保留；不提供V1网页“确认后消除异常”或改阈值。来源关联、规则版本、snapshot_id和evidence_ref支持回溯。历史观测90天、访问记录180天已获用户确认，见DECISIONS D06；Linux四表已建并开始追加真实记录；成功日兜底调用自有保留期清理，未触及源台账/备份。未做90/180天实际老化验收。

## 实现边界

台账每页500/最多20页；journal先按生命周期/固定设备结束标记筛选，再按游标最多20页；展示不带原始业务payload。Lucullus父日志读取总量上限2MB，只导出固定开始/六步骤/终止标记；训练日志末64KiB有界解析。超预算、缺标记、必要子身份不全、调度摘要过期均为缺口，不能当全绿。

五个外部/历史备份暂用unconnected适配器，只显示未知和既有调查说明；无周期的手工QC扩展/报告预览保留在盘点，尚无独立运行卡片。备份仅读取元信息和已有校验报告摘要，不重算hash、不执行恢复目录检查；设备心跳按父窗口关联，其他班次心跳不能替代。SHA匹配只标scope_verified，恢复仍not_verified；没有找到可绑定每日产物的恢复实测记录。

尚未实现的增强：备份大小7次中位数异常、完整维护有效期/审批、Persistent补跑标识、原始日志所有业务错误语义、自动“已恢复”摘要、外部Windows/IT/VM读取。V1当前正常表示所列必要执行证据完整，不把这些增强或外部覆盖写成已实现。
