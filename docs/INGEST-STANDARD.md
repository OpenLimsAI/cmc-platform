# 仪器归档接入规范（Stage 1 通用标准）

> **这个文件是什么**：`cmc-instrument-ingest` 里**与具体仪器无关**的原则、约定和操作规矩。
> 新增一台仪器时照本文办，不要现想；改动本文等于改架构，必须走变更控制。
>
> **分工**：
> - 本文 = 通用规范（怎么接、怎么命名、用什么账号、什么策略、怎么校验）
> - `CLAUDE.md` = 项目铁律 + 当前状态 + 待办
> - `docs/source-survey-<代号>.md` = 某台仪器的**数据源实测记录**（事实，不是推测）
> - `docs/SETUP-<代号>.md` = 某台仪器的**部署步骤**
>
> 与 `~/code/CLAUDE.md` 总纲冲突时，**以总纲为准**，并停下来找负责人确认。

---

## 0. 适用范围与定位

本项目**只做 Stage 1：从仪器侧只读拉取 → 校验 → 归档到 NAS**。
不解析业务字段、不入库、不做分析。每台仪器的解析入库（ETL）各自独立成 repo。

**法规定位（写进 SOP，别自己加戏）**：法规意义上的原始记录是**仪器机内数据/审计追踪**；
仪器导出的文件是副本，NAS 归档是副本的副本。本系统是**分析数据源 + 业务备份**，
**不是** Part 11 原始记录保存系统。这个定位能显著降低验证等级，不要在代码或文档里暗示相反的意思。

## 1. 通用铁律

1. **源挂载点永远 `ro`。** 脚本启动时自验：能写入就立即中止（`SystemExit(3)` + CRITICAL 告警）。
   这是保护仪器数据的第一道锁，任何情况下不得移除。
2. **校验不过就不归档——但"坏"特指损坏，不是"结构复杂"。**
   真损坏（读不出、解不开、空文件）→ 拒收；结构古怪但完好（多种行宽、带 BOM、字段数异常）
   → **照常归档，只告警**。宁可告警缺一天，也不能把损坏数据写进底本；
   但更不能因为"看不懂"就把可救的主数据源丢掉。
3. **归档区 append-only。** 已归档的底本**绝不覆盖**。源文件内容变化 → 另存
   `<原名>.rev<时间戳><扩展名>` 并告警，原件保留。数据修正走记录，不改历史。
4. **凭据绝不进仓库。** `.gitignore` 必须挡 `*.cred` / `*.env` / `*_state.json`，只提交 `*.env.example`。
   密码只用 `read -s` 输入，不写进命令行、不进 shell 历史、不贴进聊天/截图。
5. **不用"业务数据陈旧"做健康告警。** 仪器停机两三周是常态，用它告警必然天天误报，
   最后没人看告警——那才是真正的失效。健康信号要选**与做不做样品无关、节奏固定**的数据源
   （例：FLEX2 每晚 23:30 的数据库备份）。没有这种数据源的仪器，就用"脚本自身是否按时跑完"当信号。
6. **真库建表走 `cmc-schema-migrations`。** 本项目 `sql/` 只是本地测试镜像，绝不在生产库上跑。
7. **Stage 1 只用 Python 标准库**（无第三方依赖）。Stage 2 才可以用 pandas / psycopg。

## 2. 命名与目录约定

### 2.1 机器名（贯穿 NAS 所有目录的唯一标识）

```
<工作站主机名或仪器序列号>_<厂商/型号简称>
```

例：`T281240040C_Nova`（FLEX2，用 Analyzer ID）、`C4V61257XH_ViCell`（用工作站主机名）。

- 优先用**仪器自己的唯一标识**（Analyzer ID / 序列号）；没有就用工作站主机名（`nmblookup -A <ip>` 查）。
- **一旦确立不再改名**。改名等于在 NAS 上另起炉灶，历史归档会断成两截。

### 2.2 NAS 布局（`/mnt/ttlab-backups` = `//10.0.6.100/ttlab_backups`）

```
TTLab_Backups/
├── Daily/<机器名>/…            # 数据本体，子目录名镜像仪器侧的目录名
├── State/<机器名>_backup_state.json   # 增量记账
├── Checksums/<机器名>/*_SHA256_Compare_<版本>_<时间戳>.csv
└── Logs/<机器名>/<机器名>_<时间戳>.log
```

- **数据目录名镜像仪器侧**（FLEX2 → `Results/` `Database/`；Vi-CELL → `data/` `export/` `images/`）。
  仪器怎么组织，归档就怎么放，**不重新设计结构、不改名、不重排**——底本要能一眼对回源头。
- **记账目录放 NAS 根级、按机器名分**，不塞进 `Daily/` 的数据目录里。所有设备一致。
- 已存在的目录（哪怕当初是手工建的、大小写不统一）**沿用，不要为了整齐去改名**。

### 2.3 仓库布局

```
<代号>/
├── <代号>_ingest.py            # 采集脚本，仅标准库
└── <代号>-ingest.env.example   # 配置样例（真配置放 /etc/instrument-ingest/）
tools/
├── run-ingest.sh               # 统一采集入口（一次跑完所有设备）
├── ingest-alert.sh             # 统一告警出口
├── heartbeat_check.py          # 心跳巡检
└── deploy/                     # **所有 systemd 单元都在这里**，不按设备分散
docs/
├── source-survey-<代号>.md     # 数据源实测记录
└── SETUP-<代号>.md             # 部署步骤
```

> systemd 单元**不放进各设备目录**：定时器是按"时段"组织的（夜班全量 / 白天不含图片），
> 一个单元同时管所有设备，放在哪个设备目录下都不对。

`<代号>` 用小写仪器简称（`flex2`、`vicell`）。**第二台仪器来了才建平级目录，不做提前抽象。**

## 3. 账号与凭据

| 用途 | 账号 | 凭据位置 | 权限 |
|---|---|---|---|
| 读仪器共享 | **`instrument_reader`**（所有小仪器统一） | `/etc/instrument-ingest/<代号>.cred` | 只读、非管理员、只授权那**一个**共享 |
| 写 NAS 归档区 | `backupuser` | `/etc/instrument-ingest/nas.cred` | 对 `ttlab_backups` 可写 |
| 下游 ETL 读 NAS | `etl_reader` | 各 ETL repo 自管 | 只读 |
| Linux 运行用户 | `flex2ingest`（uid 999） | — | 非登录用户 |

- 凭据文件一律 `chmod 600`、`chown root:root`。
- **权限收口靠"每台共享单独授权"，不靠账户名区分**：账户是同一个，但在每台仪器电脑上
  只把它加到那一个只读共享，且进不了系统盘（验收标准：`smbclient` 访问 `C$`/`ADMIN$`
  必须 `NT_STATUS_ACCESS_DENIED`）。
- **域管理员/本地管理员账号只用于一次性勘察**，密码当场输入、绝不落盘，用完即止。
  常驻任务永远用只读账户。理由：万能钥匙挂在门外，服务器一旦被拿下等于整个域被拿下。
- 运行用户名带 `flex2` 是历史遗留（NAS 是以 `uid=flex2ingest` 挂载的，改名要连挂载和
  所有归档文件属主一起改）。**别顺手改**，要改就当独立运维任务做。

> 遗留项：FLEX2 目前仍用旧账户 `nova_export_reader`，尚未迁到 `instrument_reader`。

## 4. 挂载规范

```
//<ip>/<共享>  /mnt/<代号>  cifs  ro,credentials=/etc/instrument-ingest/<代号>.cred,vers=<实测值>,uid=flex2ingest,gid=flex2ingest,file_mode=0440,dir_mode=0550,iocharset=utf8,nofail,_netdev,soft,noserverino  0  0
```

- **`ro` 不可省略。**
- **`vers=` 必须写实测值，不许猜。** `mount -o vers=` 是"就用这版"，不支持就报
  `mount error(95) Operation not supported`。老机器常见：Win7 只到 **2.1**。
  （注意 `smbclient -m SMB3` 是"最高用到 SMB3"、会自动降级，两者语义不同，别混。）
- `nofail` + `soft`：网盘断链时不要卡死开机、不要挂死进程。
- 脚本自身仍要做**预检 + 只读自验**，不能只依赖 fstab 写对了。

## 5. 采集策略：先给数据源分类，再选策略

**接入任何新仪器，第一步是把它的每个数据源归到下面某一类。** 分错类会直接导致数据永久丢失。

| 类型 | 特征 | 策略 | 例子 |
|---|---|---|---|
| **A 一次写死** | 每次运行产生一个文件，之后不再改 | 按**文件名**增量；已归档的不重读、不重算哈希 | Vi-CELL 的 `Data/*.txt`、`Export/*.xls` |
| **B 持续追加** | 同一个文件整月/整周在长 | **每次内容变化存一份带时间戳的快照**，不覆盖 | FLEX2 月度 CSV |
| **C 每晚覆盖** | 只留最新一份，旧的直接没了 | **每天必抓，且要赶在覆盖前**；漏一天即永久丢失 | FLEX2 `Database/Backup_*` |
| **D 目录型资产** | 一次运行产生一整个目录的文件 | 只比对**目录名单**，不钻进已归档目录；**整目录成功才记账** | Vi-CELL `Images/<样品>/` |

判类型的两个关键问题：

1. **"我今天不抓，明天还在吗？"** 答"不在" → C 类，频次必须压过它的覆盖周期。
2. **"这个文件明天会不会变大？"** 答"会" → B 类，必须存快照而不是覆盖同名文件。

**D 类特别注意**：判断"新目录"只能靠**目录名**，不能靠目录的修改时间——目录时间戳会被
搬文件夹、批量操作整体刷掉（Vi-CELL 实测踩过）。

**别在归档层做过度抽象**：只有一台仪器时就写一个目录，第二台来了再加平级目录。

## 6. 完整性校验（SHA-256）

**双向校验，缺一不可：**

1. 从源读出内容，当场算 `h1`（对**内存里的字节**算，不是再读一次源）
2. 原子写入 NAS
3. **回读归档文件**算 `h2`
4. `h1 == h2` 才算归档成功

不一致时：**删除坏副本 + 不写状态 + CRITICAL 告警**，下次运行自动重来。
不允许"写完就算成功"——CIFS 静默截断是真实存在的。

**比对文件**：每次运行在 `Checksums/<机器名>/` 输出一个 CSV，列固定为

```
Relative_Path, Local_Path, NAS_Path, Change_Type, Local_Size, Local_MTime,
Local_SHA256, NAS_SHA256, match_status
```

`match_status ∈ {MATCH, MISMATCH, DRY_RUN}`。空跑也要留只含表头的文件——
"这次什么都没做"和"这次没跑"必须能区分开。

**读取稳定性**：读源文件前后各 `stat` 一次，大小或 mtime 变了就重试
（默认 4 次、间隔 3 秒）。防的是读到仪器正在写的半截文件。

## 7. 时间戳规范

**归档副本必须保留源文件的修改时间**（`os.utime`，且必须在 `rename` **之后**设置）。

> ⚠️ 这一条 2026-08-03 被实测推翻过一次：最初写的是"在 rename 之前设以保证原子"，
> 但**本 NAS 的 CIFS 上 `rename` 会把 mtime 重置为当前时间**，先设等于白设。
> 该缺陷静默发生——内容 SHA-256 全绿、文件数正确，只有专门比对时间戳才看得出来。
> 设完应立刻回读确认。注意本地 Samba **不复现**此行为，本地测试会误判为通过。

- 实测仪器导出文件的**修改时间 == 文件内部记录的生成时间**（Vi-CELL 抽查四个文件，
  含 2025 年的，秒级一致）。这是有溯源价值的元数据。
- 不带过去的话，NAS 上所有文件都会显示成"归档那天"，按时间排序、按时间找文件全废。
- **Windows 的"创建时间"读得到、但写不回**：
  - **读**：`os.stat()` 拿不到（`statx` 的 `st_birthtime` 为 `None`，`stat` 显示的 `Birth` 是
    内核用 mtime 伪造的假值），但 CIFS 客户端通过扩展属性
    `os.getxattr(p, "user.cifs.creationtime")` 暴露了它（8 字节小端 FILETIME）。
    实测 2.6 ms/文件，与 `smbclient allinfo` 逐秒吻合。
  - **写**：Linux **没有**设置创建时间的系统调用，任何复制方法、任何源都改变不了这一点。
  - **正确做法**：作为**元数据采集并独立记录**（见 `DATA_INTEGRITY_METADATA_DESIGN.md`），
    不尝试还原到副本上。这是审计项 MD-001 的结论。
- **业务日期以文件内容为准**，不以文件系统时间为准。ETL 必须从文件内部取日期。

## 8. 增量与状态

**状态文件**：`State/<机器名>_backup_state.json`，同时在本地
`/var/lib/<代号>-ingest/` 写一份副本（NAS 不可达时仍留痕）。读取时 NAS 优先、本地兜底。

约定字段：

```jsonc
{
  "machine_name": "...", "script_version": "...", "last_run": "YYYY-MM-DD HH:MM:SS",
  "<类型>_files": { "<文件名>": {"sha256": "...", "size": 123, "archived_at": "..."} },
  "<类型>_dirs":  { "<目录名>": {"file_count": 50, "archived_at": "..."} }
}
```

**幂等是硬要求**：同一个脚本连跑十次，结果必须和跑一次一样。加跑不能有副作用
（这样才能放心提高频次、放心手动补跑）。

**跳过的判据要便宜**：A 类先比文件名 + 大小，命中就跳过，**不读文件内容**。
只有大小对不上才读、才算哈希。否则日常一趟要把上千兆经 SMB 拉一遍。

**半截不记账**：D 类目录只有全部文件都校验通过才写进状态；中途失败则整个目录不记账，
下次重来。宁可重传，也不能让漏掉的文件被永久跳过。

## 9. 频次与告警

### 9.1 运行时刻表（本机唯一权威，改时刻先改这里）

**一个时间点把所有设备跑一遍，不按设备拆定时器。**（2026-08-05 定）
两台仪器每趟只有几十个小文件，按设备错峰的收益极小，却让"今天几点该跑什么"
变得难记难改。现在只有两个定时器：

| 时刻 | 单元 | 跑什么 |
|---|---|---|
| `02:00` | `instrument-ingest-night.timer` | **全量**：所有设备当天新增的一切，含 Vi-CELL 图片、FLEX2 的 Database 备份 |
| `11:45` | `instrument-ingest-day.timer` | 所有设备，**不含图片** |
| `16:00` | 同上 | 所有设备，**不含图片** |
| `09:00` | `heartbeat-check.timer` | 心跳巡检（不采集，只检查昨夜跑没跑、成没成功）|

两个采集单元都调 `tools/run-ingest.sh <day|night>`，它逐台调用各设备的采集脚本。
**采集脚本本身不合并**——一台仪器故障不许拖垮另一台，所以 wrapper 里前一台失败后一台照跑，
最后汇总一条批次告警。

排班理由，改之前先读懂：

- **图片只在夜里抓**：图片段读的是仪器工作站共享，白天仪器在用会撞上文件占用
  （2026-08-04 实测反复 `Device or resource busy`，最后跑满超时被杀）。
- **02:00 不能再往前挪**：Nova 23:30 做数据库备份，太早会读到半截。
- **下游 ETL 固定滞后 20 分钟**（`rd-vicell-etl` / `rd-nova-etl` 排 `12:05` / `16:20`）。
  所以采集 timer 的 `RandomizedDelaySec` **必须为 0**——一加随机延迟，
  ETL 就可能跑到备份前面，当天数据入不了库。改采集时刻要同步改那两个仓库的 timer。

### 9.2 频次原则

**频次由最紧的那个数据源决定**：

- 有 C 类（每晚覆盖）→ **每天至少一趟，且必须排在覆盖动作之后、下次覆盖之前**。
- 只有 A/B/D 类 → 每天一趟即可；想缩短延迟可以加跑，因为幂等所以无副作用。
- 用 systemd timer 托管（`User=`、`RequiresMountsFor=`），不要用 cron 裸跑。
- **新增第三台仪器不加新定时器**：在 `tools/run-ingest.sh` 的 `case` 里加一行，
  并把它的 `EnvironmentFile` 加进两个 `instrument-ingest-*.service`。

**告警分级**：

| 级别 | 用在什么情况 | 例子 |
|---|---|---|
| `CRITICAL` | 数据可能丢失或已被污染，需要人当天处理 | 源挂载可写、SHA 不一致、NAS 写入失败、预检失败 |
| `WARNING` | 需要人知道，但不影响本次归档完整性 | 单个文件读取失败、结构异常、历史文件内容变化 |

> severity 只允许 `CRITICAL` / `ERROR` / `WARNING` 三个值。历史代码里出现过
> `WARN` 与 `WARNING` 两种拼法，现由 `alerting.py` 内部归一化（见 `BACKUP_MONITORING_DESIGN.md`）。

告警走 `ALERT_CMD "<级别>" "<消息>"` 外部命令，脚本本身不绑定任何通知渠道。
同时**结构化落盘** `Alerts/<机器名>/alert_YYYYMMDD.jsonl`（NAS + 本地双写）。

**必须同时具备两样东西，缺一不可：**
1. **告警外呼端点**——只落盘不外呼等于没人知道（审计 MD-004）；
2. **独立于采集程序的心跳巡检**——采集脚本没跑时它自己不会上报"我没跑"（审计 MD-005）。
   心跳文件 `State/<机器名>_heartbeat.json` 每次运行都写（含崩溃与预检失败），
   `last_success_time` 仅成功时更新，这样"失败"与"根本没跑"可区分。

## 10. 变更控制

- 改动逻辑必须**递增脚本内 `SCRIPT_VERSION`** 并在 `CHANGELOG.md` 登记，写清"为什么改"。
- 数据源的新发现写进 `docs/source-survey-<代号>.md`，**标注是实测还是推测**，实测要带日期。
- 部署侧改动（挂载参数、timer 时刻、账号）同步更新 `docs/SETUP-<代号>.md`。
- 流程：Mac 改 → `git push` → Linux `/opt/cmc-instrument-ingest` `pull` → 跑。
  **不手工拷贝、不本地魔改后不提交。**

## 11. 新增设备接入清单

按顺序走，**别跳步**：

- [ ] **1. 勘察连通性**：`ping` / 445 端口 / `nmblookup -A <ip>` 取主机名 → 定机器名
- [ ] **2. 申请只读共享**：仪器电脑上给 `instrument_reader` 开**单个目录**的只读共享
- [ ] **3. 验权限边界**：`smbclient` 试 `C$`/`ADMIN$`/`D$`/`E$`，**必须全部 ACCESS_DENIED**
- [ ] **4. 试挂载**：确定实际 SMB 版本（从 3.1.1 往下试），`ro` 自验必须写入失败

## 12. 失效检测：这套系统最可能怎么死

**备份系统的典型死法不是报错，是静默地什么都不做。** 下面四种失效，靠"看告警"是发现不了的
——因为它们根本不产生告警。必须有专门的检测。

### 12.1 脚本根本没跑（最危险，优先级最高）

timer 被禁用、服务启动失败、机器重装后忘了恢复、凭据过期——这些情况下脚本**一次都不会执行**，
自然也不会发出任何告警。等到需要数据时才发现断了三个月，已经晚了。

**对策：外部心跳检查（dead man's switch）。** 每台仪器的
`State/<机器名>_backup_state.json` 里有 `last_run`。用一个**独立于采集脚本**的每日任务
扫描所有机器的状态文件，任何一台 `last_run` 超过约定时限（建议 = 正常频次 × 3）就告警。

关键是**这个检查必须独立**：不能由采集脚本自己上报"我跑了"，因为它没跑的时候也不会上报。

> 这一条尤其重要，因为我们（§1 铁律 5）明确**不用"业务数据陈旧"做告警**——
> 那就等于放弃了一个天然信号，必须用心跳把它补回来。

### 12.2 源端文件被删除

归档区是 append-only，源端删了我们不会跟着删（这是对的）。但**我们应该知道它被删了**，
而不是几个月后偶然发现。

**对策：每次运行比对"状态里已归档"与"源端现存"，差集写进日志并 `WARN` 告警**（只报告，不删除）。

> 实例：Vi-CELL 首跑（2026-08-03）发现 3 个 2026-07-02 做的样品在工作站上已消失，
> 只有 NAS 上还有——是搬文件夹时漏的。若没有这次比对，没人会知道。

### 12.3 归档文件静默损坏（bit rot）

文件躺在 NAS 上几年，可能因磁盘/传输问题悄悄坏掉，而目录还在、大小还对。

**对策：定期抽样复核。** 每季度随机抽 N 个已归档文件重算 SHA-256，与
`Checksums/` 里当初的记录比对。对小体量目录（如配置、审计追踪）可以每年全量复核一次。

### 12.4 备份能存但不能用

**没验证过恢复的备份，不算备份。** 常见问题：文件能取回但打不开（编码坏了、
`.xls` 是老格式新软件不认）、或者取回来才发现少了配套文件。

**对策：恢复演练，建议每半年一次。** 随机抽 10 个文件从 NAS 取回，做三件事：
① 校验 SHA 与记录一致；② 用实际软件打开其中一个 `.xls` 和一个 `.txt`，确认内容可读；
③ 记录演练结果与日期。这是审计最爱问的一项，也是唯一能证明"备份有效"的证据。

## 13. 保留、容量与单点风险

### 13.1 保留策略

归档区**永久保留、只增不删**。这是"底本"的定义，也是本项目存在的理由。
任何清理/归档到冷存储的动作都属于架构变更，必须找负责人，不允许运维层面自行决定。

### 13.2 容量

**接入新仪器前必须先估算增量并确认 NAS 余量。** 估法：
`每天样品数 × 每样品体积 × 365`，图片类资产要单独算（它通常比数据本身大两个数量级）。

> 现状（2026-08-03）：NAS 总 84 T、已用 25 T、**余 60 T**。
> Vi-CELL 首次回补约 116 GB（其中图片 115 GB），日常约 1 GB/天。容量不是近期约束。

**每季度看一次余量，低于 20% 就要提前规划**，不要等写满——写满时正在跑的归档会失败，
而失败当天的 C 类数据（每晚覆盖型）会永久丢失。

### 13.3 单点风险（需要和 IT 确认，不是本项目能单独解决的）

- **NAS 是不是唯一副本？** RAID 不是备份。磁盘阵列坏了、机房出事，归档就没了。
  需要确认 `ttlab_backups` 有没有快照、有没有异地或离线副本。
- **写账号能删东西。** 我们用 `backupuser` 对归档区可写，也就意味着**可删**。
  服务器一旦被入侵或脚本写错，理论上能把整个归档区清掉或加密（勒索软件的标准剧本）。
  最稳妥的解法在 NAS 侧：**开启快照/版本保留，或对归档目录启用 WORM（一次写入不可改）**。
- **仪器时钟。** §7 的时间戳全部来自仪器电脑的时钟。时钟漂移或时区/区域设置被改，
  日期就是错的（FLEX2 就出现过日期格式从 `M/D/YYYY` 变成 `YYYY-M-D`，说明区域设置被动过）。
  仪器电脑应加入域并同步时间；接入时记录一次时钟核对结果。

### 13.4 仪器退役

仪器停用后：停掉 timer、在 `README` 表格标注"已退役 + 日期"、
**归档区原样保留不动**、状态文件保留作为最后一次归档的证据。
不要删除目录，也不要把它"整理"到别处——历史链条断了就接不回来了。

## 14. 已知的通用坑（都是实机踩过的）

1. **别默认"这个源是那个源的超集"。** FLEX2 和 Vi-CELL 都出现过两个数据源**时间段互补**、
   各缺一大块的情况。必须逐月对数量，别靠抽样。
2. **老机器的 SMB 版本要实测。** Win7 只到 SMB 2.1，`vers=3.0` 直接挂不上。
3. **目录的修改时间不可信**，搬一次文件夹就全刷了。判新旧只能靠名字。
4. **NAS 归档区有属主**，用错用户跑会全程 `Permission denied`（好在是写入前失败，不产生半截文件）。
5. **仪器电脑上可能已经有别人的备份脚本/快捷方式**，接入前先问清楚，别两套程序踩同一批文件。
6. **老 SMB 服务器在仪器使用中可能被扫描拖垮（SMB2 信用耗尽）。**
   实测 Win7 的 SMB 2.1：仪器自身密集读写时，我们扫描上万文件会把 SMB2 信用池耗到 0，
   客户端永久阻塞在 `wait_for_free_credits`，`soft` 挂载无效（不是超时，是流控死锁）。
   诊断看 `/proc/fs/cifs/DebugData` 的 `Number of credits`。恢复：杀掉阻塞进程即可，
   挂载会自行恢复。**对策：采集时段必须避开仪器使用高峰**——这也是日常 timer
   排在凌晨的真正理由之一，不只是为了避开带宽竞争。
   ⚠️ 更要紧的是：把信用池耗干可能影响**仪器自己**的文件操作，有干扰实验的风险。
7. **systemd 的 `.timer` 不支持行尾注释。** `Persistent=true   # 说明` 会让整个值被忽略
   （实测某 ETL 的 timer 因此 `Persistent=no`，断电补跑一直是失效的）。注释必须单独一行。
   用 `systemctl show <unit> -p <Key> --value` 核实解析结果，别只看文件内容。
8. **操作员的命名习惯没法用程序修**（下划线/横杠混用、批号拼进样品名），
   这属于 SOP 问题，写进待办交给人，别在归档层做"智能"清洗。
