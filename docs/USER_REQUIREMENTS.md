### 2026-11-05 凌晨 ETL 调度补齐（用户已确认）

用户要求每次仪器归档计划后20分钟执行ETL，并确认Nova与Vi-CELL一起补齐：归档仍为02:00/11:45/16:00，两个ETL改为02:20/12:05/16:20。新增凌晨计划首次执行为2026-11-06 02:20（北京时间），不补跑今天或此前未安排的凌晨任务。固定20分钟是相对归档计划启动时刻，不是等待归档结束的事件触发；归档超时或失败仍显示上游风险。

只调整版本管理的systemd timer、监控计划及必要的生效日期判定，不改源ETL解析/入库、归档程序、数据库、权限或页面操作。验收：三次实际日历与仓库一致、随机延迟仍为0、原白天计划保留；新增计划生效前不生成漏跑或逾期，生效后正常检查；发布不主动启动源ETL或归档，首次自然凌晨执行另行验收。

查看总览、异常、任务详情、有界运行历史和脱敏证据；分别显示最近尝试/成功、计划时刻、耗时、量、水位、采集时间与范围。备份执行、产物、完整性、恢复验证分开；没有验证不能显示可恢复。

不提供重跑、恢复、调度/阈值编辑、任意shell/SQL/文件下载或自动修复；新增面向人的告警通知和整机外部存活监测需另立需求（任务结束通知是内部采集触发，已纳入D09方案）。同机页面不能证明整机/网络/Hub故障已覆盖。

新增P16已确认：每份Linux每日MDM备份成功后，由MDM独立配套执行器在临时Docker PostgreSQL中自动恢复验证，monitor只读展示同份产物报告；不在页面启动恢复。用户明确确认两仓修改、测试及Linux发布；不覆盖其他数据库或仪器文件备份。验收要求备份/验证分别展示、基线与备份时点一致、验证缺口不显示正常，详见ARCHITECTURE/MONITORING_RULES及TEST_ACCEPTANCE新增章节。
