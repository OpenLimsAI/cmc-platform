# 01 · 项目说明与准入

> 版本：0.4｜日期：2026-10-02｜状态：Mac 已实现，验收部分完成；Linux 未发布。

## 1. 定位与用户决定

项目名 `cmc-water-system-dashboard`，显示名称“制药用水看板”。围绕纯化水、注射用水和纯蒸汽的 LIMS 检验数据，提供按取样点、检项和期间的趋势、汇总、明细与来源核对。

已确定：先在 Mac 使用现有数据库开发，Mac 验收通过后发布到 Linux；独立项目目录和代码仓库；Hub 唯一入口；通过 MDM 分配“仅查看”和“查看＋导出”两档权限；趋势默认当前日期向前一年，提供季度、半年、年度快捷范围，并可导出趋势图及对应原始数据表。当前为文档阶段，应用、角色和服务尚未建立。

目标使用人群工作设想为 QC、QA 和水系统相关人员，实际名单与数据访问范围由负责人确定。当前数据来自 GMP LIMS 的历史快照；数据来源属于 GMP 不等于看板已被验证。开发与试用输出的用途为趋势核对，正式受控用途另行确认。

## 2. 范围与分期

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| A：文档与数据预检 | 定义来源、规则、权限、页面；复核 Mac 结构/授权/覆盖与取样点映射 | 关键依赖有证据；待确认事项有编号 |
| B：Mac 实现 | 主看板、近一年默认及季度/半年/年度快捷趋势、明细追溯、汇总、图像/原始数据表导出；Hub 与 MDM 两档权限接入 | 数据/算法/权限/浏览器验收通过，残留项记录 |
| C：Linux 发布 | 相同代码版本、生产配置、数据链路和角色部署 | 数据到位、Hub 路由与角色实测通过，发布记录齐全 |
| D：按用途扩展 | 警戒/行动判断、正式受控报告等；生产日常趋势的快照策略在 C 阶段完成 | 用途、业务口径、审计和验证要求先确定 |

一期必做为 FR-01–FR-11、FR-13 及“未配置限度”的正确提示；FR-12 的实际限度判断在规则确认后按用途启用，属于条件功能，不作为无配置情况下的 Mac 验收阻断项。一期数据范围为现有 LabVantage 水样及已版本化结果规则。SCADA 在线信号、设备控制、取样任务登记、原始结果录入/修改、电子审批和偏差处理属于后续另行定义的需求。数值趋势与定性结果均可展示，只有确认的规则才能产生限度判断。

## 3. 系统职责

| 项目 | 职责 |
|---|---|
| qc-lims-etl | Oracle → raw → QC staging；关联和最终参数规则；上游运行台账 |
| 本项目 | 只读消费分析数据；规范化展示、趋势、汇总与导出；业务 API 权限 |
| cmab-hub | 磁贴与角色显隐、统一入口、路由、会话母本 |
| cmab-mdm-platform | 账号、角色分配、令牌签发/刷新、会话策略及其审计 |
| cmc-schema-migrations | 共享分析库结构及授权迁移；变更前核对消费者 |

## 4. 白皮书 C01–C15 全项核对

| 编号 | 本项目回答 | 状态/完成条件 |
|---|---|---|
| C01 数据库/schema | 读取 `cmc_analytics.staging`；新增分析/配置对象仍归分析库 | 数据起点已定；新增 schema 如需要另行设计 |
| C02 schema 命名 | 一期复用既有 schema；不新增 raw schema | 新对象按总纲命名并迁移 |
| C03 权威主数据 | 账号角色来自 MDM；设备如需引用来自 MDM；取样点权威源待核实 | OP-01 |
| C04 新主数据归属 | 取样点映射先查 LIMS/既有 dim，确认后归权威源或明确版本的分析映射 | OP-01；不在前端硬编码成为权威字典 |
| C05 业务批号 | 水样不要求批号；源 `u_batchno` 若展示适配为 `batch_number` | 不改源字段与源值 |
| C06 命名 | 标准字段小写 snake_case、内部数字 ID 保留语义 | 设计/代码检查 |
| C07 审计 | 登录/角色审计归 MDM；本应用查询/导出记录设计见 docs/05 | 最终级别、留存和责任 OP-09 |
| C08 GxP 范围 | 当前开发及趋势核对；正式用途、规则/验证范围未定 | OP-08；用途扩展前确定 |
| C09 水位 | 本项目不重复抽取；复用 QC 上游 job 的运行台账 | 上游周期更新 OP-07；不能把别的 job 成功算为 QC 新鲜度 |
| C10 GitHub | 独立仓库计划名与目录同名 | OP-10；尚未创建 |
| C11 数据重叠 | LIMS 为结果权威源，本项目只读二次使用 | 代码与账号双重限制 |
| C12 GMP 快照 | Mac 既有历史 XLSX 派生 staging 用于开发；Linux 日常趋势需明确截止时间与快照策略 | 现有 staging 刷新不等于不可变 `snap_gmp`，OP-06 |
| C13 前端 | React + TypeScript + Vite + Ant Design + React Query；ECharts | 工作设计，版本随依赖核实 |
| C14 后端 | FastAPI + SQLAlchemy 2 + Pydantic + asyncpg；uv | 工作设计 |
| C15 发布 | Mac → GitHub → Linux `/opt/cmc-water-system-dashboard` + systemd/nginx + Hub | 固定提交、迁移及数据各自验收，docs/08 |

## 5. 成功标准

同一条件下页面、API 和导出一致；样品与结果能够回溯；计数口径不会把参数行当检测次数；权限经 Hub 与直接 API 均验证；数据缺失或未确认限度明确显示；Mac 验收证据支持 Linux 的同版本验收。

准入表是设计核对，不是已经全部通过。OP 编号见 [决策台账](10-decisions-open-items.md)。
