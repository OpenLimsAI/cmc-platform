# 04 · 水系统分析规则

> 版本：0.4｜日期：2026-10-02｜状态：Mac 已实现，验收部分完成；Linux 未发布。

## 1. 规则层次与版本

来源参数选择复用 `water_system_v1` 与 `water_conductivity_method1_numeric_v1`；本项目新增的展示、解析和统计规则采用独立版本，工作版本名 `water_dashboard_analysis_v1`。版本名目前为设计，不代表算法已验证。

每个结果保留上游选择规则及原值。方法规则变更由上游维护；本项目调整分析口径时，记录旧/新定义、影响范围和对账证据。

## 2. 上游已有最终参数口径

| 检项 | 现有上游口径 | 看板处理 |
|---|---|---|
| pH | v1 `结果` | 精确数值可作趋势，方法分组 |
| 不挥发物 | v1 `残留残渣` | 先核对数值格式和单位 |
| 亚硝酸盐、氨、硝酸盐、重金属 | 对应 v1/v2 `结论` | 定性分类与原文明细 |
| 外观、性状 | 对应版本 `结论` | 定性分类与原文明细 |
| 微生物限度 | v1/v2/v3 `报告值` | 区分精确值与 `<1` 等删失值 |
| TOC | v1 `TOC报告值`、v2 `结果` | 单位/方法比较组确认后作趋势 |
| 电导率 | 普通方法 `结果`；旧纯化水按上游规则选报告值/结果；方法1保留结论并补数值 | 数值趋势与结论分别展示，同一次检测不重复计数 |
| 细菌内毒素 | v1/v2 `结论` | 先展示定性结果；不把试剂量/限度当实测值 |
| 酸碱度 | v1/v2 `结果判定` | 定性结果 |

表为上游规则摘要，准确的 `paramlistid/version/variant/param` 条件以 QC 代码为准。不得根据检项名称正则扩展最终结果选择范围。

## 3. 状态、期间与计数

上游宽表包含 `Completed` 和 `Reviewed` 且参数 `releasedflag=Y`；`Completed` 为测完未复核，`Reviewed` 为样品已复核状态。样品状态不能单独证明 QA 身份或产品放行，参数已发布也不等于样品/批次已放行。工作设计：默认 `Reviewed`，用户可切换 `Completed` 或两者；总览、图、汇总和导出共享状态筛选。

期间工作设计采用 `trend_dt`。页面起止日期均包含用户选中的日历日；API FilterSpec 使用亚洲/上海日期 `date_from`（包含）和 `date_to`（不包含），前端把页面终止日转换为下一日作为 date_to。后端再根据源时区将日历边界转为查询时间。已核对 staging 时间列在迁移中为 timestamptz，但仍须核实源时间和导入时区，数据库类型本身不能证明源采样时刻正确。月/季度/年边界统一使用同一规则。

趋势日期默认及快捷规则：

- 没有指定日期的首次进入，按后端 context 的 Asia/Shanghai `current_date`，选择当天向前 12 个日历月至当天；两端日期包含。
- “季度趋势（近 3 个月）”“半年趋势（近 6 个月）”“年度趋势（近 12 个月）”均截至今天，按日历月回溯；这是滚动范围，期间汇总中的自然季度/年仍按各自边界统计。
- 保留自定义起止日和 URL 恢复的明确日期；已指定日期优先于默认范围。月末或闰日回溯时，落到目标月最后一个有效日，不按固定 90/180/365 天替代。
- 初次进入或点击快捷范围时解析并固定实际起止日；查询和导出沿用这组日期，跨过午夜不自动改变已选范围。再次点击快捷范围时取得后端最新 current_date，再按今天重新计算，避免使用昨日缓存。
- 示例今天为 2026-10-02：季度为 2026-07-02～2026-10-02，半年为 2026-04-02～2026-10-02，年度/默认为 2025-10-02～2026-10-02；三者 API date_to 均为 2026-10-03。
- 不用最新结果日期替代今天。历史快照在默认范围无结果时明确显示无结果和真实数据上下文，用户可自行改日期；不能静默切换为数据最后一年的范围。

`trend_dt_source` 必须随数据显示。横轴标“趋势日期”，只有确认 `collectiondt/eventdt` 的业务语义后才可标“采样日期”。无有效日期的结果列在质量明细，不放到伪造日期。

| 指标 | 定义 |
|---|---|
| 入选样品数 | 主看板筛选后宽表中唯一 `(source_system,s_sampleid)` 数；样品表候选量在质量核对中另列 |
| 结果行数 | 完整结果复合键的唯一行数 |
| 方法数据集数 | `source_system,sdcid,keyid1,keyid2,keyid3,paramlistid,paramlistversionid,variantid,dataset` 唯一组合数 |
| 检测次数 | 只有完整检项实例身份已核对才能计算；身份未确认时显示“方法数据集数”，不能替换标签 |

电导率方法1的 `结果` 与 `结论` 属于同一数据集；计方法数据集数时去除参数维度。重复/复测与源 replicate 保留，不擅自按样品取 MAX、平均或最后一条。

## 4. 数值解析与可比组

原始 `displayvalue` 与 `unit` 永远保留。派生 `result_kind` 工作分类为 `exact_numeric/censored/qualitative/missing/unparsed`，派生数值使用 Decimal 精度；分类与失败原因能回查。

- 精确数值：只接受核对过的数字格式；保留有效数字展示，不用浮点格式覆盖原文。
- 删失值：`<1`、`≤...`、`>...` 等保存比较符和界值，未定统计策略前不纳入普通均值/标准差。图中使用独立标记并明确界值不是实测点。
- 定性值：符合规定、未检出等保留原文；分类映射需要版本，不因文字正则自行产生“合格率”。
- 空值与未解析：分别计数、显示原值和原因，不当 0，不静默删除。
- `enteredvalue/transformvalue` 只能在对应方法已核对后作为派生数值来源；与显示值不一致时提示差异，不能通用地替换结果。

工作比较组至少包含水类型、取样点、检项 workitemid、方法 paramlistid/paramlistversionid、阶段 variantid、最终参数族和规范单位。最终参数族若尚无确认映射则按源 paramid/paramtype 分开，不能将所有名为“结果”的参数合并。不同方法版本先分组展示；合并必须有等效性依据。单位换算只采用明确映射，并保存原单位/原值、换算系数及版本；不混合不同量纲。

## 5. 汇总与限度

首期均值、最小值、最大值仅针对同一比较组中的精确数值结果行子集，同时显示总行数、精确值行数、删失行数、定性行数、未解析/缺失行数，以及唯一样品数。N 表示参与统计的结果行数，不等于独立样品或检测次数；多 replicate 不擅自平均。标题注明“精确数值结果行子集”，不能误称包含全部结果的总体统计。没有精确值时统计为 null。

警戒限、行动限、规格限分别定义，需关联水类型、取样点/系统、方法、参数、单位、生效区间、比较运算符、来源文件及规则版本。缺少配置或发生单位/适用范围冲突时显示“未配置/不适用/待确认”，不输出“正常”或超限结论。

删失值与限度比较需考虑区间：界值本身不能一律作为实测值判定。Cpk/Ppk、控制限、异常趋势/OOT、合格率及正式结论在业务口径确认前不启用。数值与文字结论不一致时显示两者并列及来源，不覆盖任何来源结果。

## 6. 完整性规则

缺编号记录进入“取样点缺失”组；有编号无名称显示编号与“名称未映射”。系统/回路归属不从编号或 source_instance 字符串拆分。存在映射变更时使用有生效期的映射，不把最新名称/归属静默覆盖所有历史。

季度或年度“覆盖率”只有具备应取样计划和明确分母才能计算；已有结果数不能证明采样计划全部完成。分母缺失时显示实际样品数与数据缺口。

分析规则对照测试见 [docs/09](09-test-acceptance.md)。限度、方法可比性、时间语义和删失统计策略对应 OP-02。

## 7. 派生规则依赖与边界

精确值解析、类型区分、分别计数和原值展示可先实现并验证；方法合并、单位换算、限度与定性判断依赖具体依据。缺单位时仍保留精确数值类别，但该记录不与单位已知的结果汇总在同一可比组；未知单位之间也不推断为同一量纲。

`trend_dt_source` 的合法标签来自上游 `collectiondt/eventdt/receiveddt/createdt`，其中 eventdt 对应宽表字段 sample_eventdt、createdt 对应 sample_createdt。全空时间时可能仍得到 createdt 标签，因此必须同时校验 trend_dt 非空，不能仅凭标签认定日期存在。
