# 两页看板整理与位置筛选设计

> 版本：0.2｜日期：2026-10-09｜状态：用户已明确WFI/PW/PS三卡片及两页范围，并授权本轮更新文档后实施代码；位置/系统归属暂停。本条更新先于代码修改，本轮代码、49/9项隔离测试和Mac只读对账已完成；真实浏览器登录后验收与Linux发布未完成。

## 1. 需求来源与页面边界

用户要求先写文档，再按文档修改代码：只保留“总览”和“取样点趋势”，删除结果明细、期间汇总、数据质量三个独立功能；总览不使用统一筛选，展示水系统重点数据；取样点趋势是核心，现有筛选与绘图先保留。调查南楼、北楼、祥泰路等位置字段，有可靠依据时加入筛选和总览分类。

| 页面 | 新职责 | 与另一页的关系 |
|---|---|---|
| 总览 | 自动展示三类水的近期数据概况、月度变化与最近更新点位 | 不继承趋势页筛选；通过侧栏进入取样点趋势 |
| 取样点趋势 | 选择水类型、点位、检项和可比组，查看原值、趋势、来源与导出 | 保留现有近3/6/12个月、自定义日期、状态及级联规则 |

侧栏只有两项，默认进入总览。筛选区域只出现在取样点趋势。趋势页面保留对应原始结果表、来源抽屉及 PNG/Excel/ZIP 导出，它们是趋势核对的组成部分。删除三个独立页面及其专用请求、状态、接口和不再使用的代码；不保留隐藏菜单或空页面。来源数据、上游选择规则和历史证据不删除，重新引入这些业务功能时另提需求。

旧 `/water/results`、`/water/summaries`、`/water/quality` 链接统一替换为 `/water/overview` 并提示“该功能已移除”；旧筛选不得影响总览。切换回趋势可保留本次会话内趋势条件，刷新趋势继续按其 URL 恢复。

## 2. 本轮明确的总览设计

用户进一步要求总览暂时只有WFI、PW、PS三个标签，内容为点位数和年度样品总数。初稿中的近30天、月度趋势、最近点位与额外卡片不实施。

| 标签 | 水类型 | 内容 |
|---|---|---|
| WFI | 注射用水 | 点位数、年度样品总数 |
| PW | 纯化水 | 点位数、年度样品总数 |
| PS | 纯蒸汽 | 点位数、年度样品总数 |

三个标签采用并排卡片，无统一筛选、年份选择或额外图表。年度采用Asia/Shanghai当前自然年1月1日至今天；本轮以此明确实现口径，页面显示年份与截至日期。总览不接收FilterSpec，不继承趋势条件。

沿用当前看板已入选结果范围：QC来源、Sample、三类水、两条来源规则，样品状态包括Reviewed与Completed。点位数为该水类型全部可用入选数据中不同非空内部samplepointid的数量，不限年度、不称系统数量或完整点位台账；年度样品总数为年度趋势日期范围内唯一(source_system,s_sampleid)数量，不是结果行数，不包含没有入选结果的待检/其他状态样品。方法1数值与结论、多参数或replicate不重复增加样品/点位；同号不同内部ID不合并。

年度采用API半开范围[当年1月1日,上海明日零点)。缺日期不计年度样品，缺内部点位不增加点位数但有有效日期的样品仍计入；原值/来源记录仍在上游保留。没有某类水时该卡片两项显示0；查询失败显示错误及重试，不能展示为0。不按最新结果日期平移统计年度。

三卡片与data_context在同一个REPEATABLE READ只读事务中获取，在SQL层聚合，不读取全部原文。总览统计版本为water_overview_counts_v1，趋势解析/比较组版本仍为water_dashboard_analysis_v1。环境与结果/装载日期线索继续明确，不能把数据截止未知写成同步完成。

## 3. 位置调查：本轮已核实事实

2026-10-09 用 `lims_reader` 在 Mac `cmc_analytics` 只读事务检查字段与水样聚合；另用已有 `QC_LIMS_READONLY` 连接正式 Oracle `lims`，在只读事务中限定查询 `MBTK.S_SAMPLEPOINT` 与 `MBTK.S_LOCATION` 的主数据及元数据。未运行 ETL、报告、迁移、角色授权或业务写入。本次数据库调查不是看板运行时连接 Oracle 的方案。

| 层面 | 已核实结果 | 能支持的判断 |
|---|---|---|
| 当前样品与宽表 | 有 `locationid`；主看板84,620行的该字段全部为空；没有已提供的厂区/楼栋分类字段 | 不能直接用现有字段做有效的位置筛选 |
| 样品部门 | `sitedepartmentid` 有迈博太科、QA、生产二部及空值；工作区域部门为空 | 部门不能当厂区或楼栋 |
| 正式取样点主表 | 当前361点，全部有 `LOCATIONID`，且都能对应位置主表；`U_LOCATIONID/U_LOCATIONLEVEL/U_ROOMAREA` 全空 | 有明确的点位→位置主键关联；不能靠自定义字段确定厂区 |
| 正式位置主表 | 当前167条；有 `S_LOCATIONID/LOCATIONLABEL/LOCATIONDESC/LOCATIONTYPE/PARENTLOCATIONID`；父位置全部为空 | 能识别房间/位置名称，尚无可用的厂区→楼栋→房间层级 |
| 位置大类 | 两张主表中只有5个点位描述明确含“北楼”（RO1–RO5，关联“5203一层制水间”）；位置名称无南楼、北楼、祥泰字样 | 不能将其他点位由房号、编号前缀或相邻点位外推到厂区 |

当前 Mac 主看板按三类水及两条规则、不限状态/日期的点位覆盖对账：纯化水40,284行／219个非空内部点位，注射用水40,419行／74个，纯蒸汽3,917行／60个。所有非空内部点位均能匹配本次正式点位主表；纯化水另1行缺内部点位，故84,619行具备这条当前主表位置关联。数字为本轮观察，不作测试固定期望，也不代表 Linux 数据。当前主表位置是“现在的主数据映射”，不能证明历史检验时位置未发生变化。

没有对全部历史样品的自由文本做全量位置推断；上述“大类未确认”只针对已核对的字段和主表，不能解释为公司没有这些厂区。

## 4. 位置与系统归属暂停

用户明确本轮先不处理位置，后续提供对照表并解释水点编号前面的数字含义，据此才能确认独立水系统及分类。当前不新增位置筛选、厂区汇总、字典、ETL或共享结构变更；不从房号、点位前缀猜测南楼/北楼/祥泰路或系统数量。第3节只读调查保留为证据，不作为当前运行配置。

对照表到位后另写需求与数据契约，区分厂区、楼栋、房间、系统和点位；记录权威来源、版本、适用范围及历史有效性，再确定迁移/上游接入和看板筛选方案。

## 5. 接口与实现影响

| 对象 | 本轮调整 |

| GET /api/v1/overview | 无参数，返回year、date_from/date_to、sample_status、point_scope、overview_rule_version、三项water_cards及原data_context信封；任何旧筛选参数422 |

| GET /api/v1/results、/summaries、/data-quality | 移除专用业务接口，旧接口404；来源追溯子路径继续保留 |
