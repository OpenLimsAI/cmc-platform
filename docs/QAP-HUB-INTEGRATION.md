# QAP 接入 cmab-hub

日期：2026-09-24。目标：质量分析看板使用 MDM 统一身份，通过 cmab-hub 的 `/qap/` 单一入口访问。本文描述代码与部署契约；是否已上线以实际 Linux 提交、服务和业务验收为准。

## 路径与网络边界

| 层级 | 地址 | 作用 |
|---|---|---|
| 对外入口 | `http://<hub>:5100/qap/` | 唯一用户入口 |
| Hub API 代理 | `/qap/api/` → `127.0.0.1:8040/api/` | 剥除 `/qap` 前缀 |
| Hub 健康检查 | `/qap/health` → `127.0.0.1:8040/health` | 只返回存活状态 |
| QAP 前端 | `127.0.0.1:5140/qap/` | Linux 静态前端，仅本机监听 |
| QAP 后端 | `127.0.0.1:8040` | FastAPI，仅本机监听 |

不新增防火墙开放端口。未登录时，QAP 跳转到 Hub `/login?redirect=/qap/`；登录成功后由 Hub 返回 QAP。QAP 不保存密码、不签发令牌，也不再提供独立登录表单。

## 权限边界

Hub 磁贴与 QAP 后端使用同一组 MDM 角色：

- `QAP_QC_GENERAL`：查看及 Excel 结构预览；正式导入仍未开放。
- `QAP_QA_RELEASE`：只读查看；不授予放行审批、导入或数据修改。

磁贴显隐只改善入口体验。所有业务 API 仍由 QAP 后端验签并检查角色；无令牌返回 401，无 QAP 角色返回 403，临时密码令牌返回 403。用户分配由 MDM 管理，不在本仓库写死人员。

## 仓库改动

QAP 仓库负责 `/qap/` 前缀、统一会话、后端权限、systemd 和本机 nginx 模板。cmab-hub 仓库负责应用磁贴、5100 反向代理及部署编排。`deploy/linux/deploy.sh` 不迁移数据库，只使用事先配置的 `cmc_analytics` 只读账号，并从 MDM 环境读取 HS256 验签密钥；缺少数据库凭据或验签材料时失败退出。

## 上线验收

1. 固定并核对 QAP 与 Hub 的完整 Git SHA，Linux 工作区必须干净。
2. QAP 后端 `/health` 返回 200；无令牌访问业务 API 返回 401。
3. 5140、8040 仅监听 `127.0.0.1`，不新增 ufw 入口。
4. Hub `/qap/` 返回 200，刷新 `/qap/release`、`/qap/stability`、`/qap/similarity` 不出现 404。
5. 无会话访问 QAP 自动进入 Hub 登录页；有对应角色的真实员工免重复登录进入；无角色员工看不到磁贴且直接请求 API 返回 403。
6. 临时密码用户不能进入；退出或会话过期后回到 Hub 登录页。

早期 `/opt/quality-analysis-platform` Next.js 测试服务已于 2026-09-24 退役：`qa-frontend.service`、应用目录及 ufw 3001 规则均已删除，端口已确认无监听。此次仅删除旧应用与暴露入口，没有删除其曾连接的数据库数据。
