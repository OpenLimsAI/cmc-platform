## 0. 铁律与方法（先读）

1. **以代码为准，不以设计稿为准**。设计稿写的是"计划"，代码才是"现状"。两者冲突时一律以代码为准（见下方 ⚠️ 已发现 2 处不符）。
2. **状态三档**：已上线→回填；部分上线→只回填已上线那部分；未上线→**不进四件套**，留在设计稿档案里。
3. **按维度推进**：一个正式文件只打开一轮、改完即收尾（加修订记录、升版本号）。顺序：**数据模型 DM → 架构 ARCH → 需求 URD → UI**（地基先行）。
4. **可回滚**：先建工作分支；每个正式文件改完一次 commit。
5. **每项验收**：执行后用清单里的【验收】去核对（codex 可独立用代码证据复核），通过才进下一项。

### ⚠️ 已发现的"设计稿 ≠ 代码"之处（回填时必须按代码写）
- **入库重构**：设计稿写"单物料 / 多物料批量 **两模式**切换"；**代码实际**是"按物料大类 4 个 Tab（试剂/耗材/标准品/色谱柱），每个 Tab 内支持多批次、多位置、无编码物料"（`IntakePage.tsx`：类型定义 :50、`activeTab` :116、4 Tab 渲染 :353）。→ 回填 URD/UI 一律按"4 Tab 形态"写，不要写"两模式"。
- **登录续期**：设计稿规划 3 步；**代码实际**只上线第 1 步（自动续期）。第 2 步"空闲登出"、第 3 步"编辑防丢"**未实现**。→ 四件套只写自动续期，不写空闲登出/编辑防丢（或仅在路线图标"规划中"）。
