## 状态与维护规则

1. 需求/验收目标与已实现行为分别描述。本次用户已明确撤销FR-08/10和FR-09独立页，按两页变更记录登记；总览三卡片已明确，位置暂停；代码未调整时保留变更前实现说明。代码未达到要求时，在 docs/10 保留差距，不能通过删减要求把它登记为完成。
2. 当前实现以所列代码为依据；环境事实以实际执行证据为依据。STATUS 汇总状态，各专项文档不复制易过期的运行结论。
3. 文档中的“待确认/未实现/未验收”分别表示决策缺失、代码缺失和证据缺失。服务部署、数据到位、隔离测试和真实身份验收分别登记。
4. 日期、计数、来源键、分组规则由 docs/03–04 定义；docs/07 引用并说明传输格式。业务修改同步需求、规则、API、测试与决定，不单改一份。
5. 历史记录按执行日期解释。“当时无仓库/未部署/无映射”不代表今天。新结论追加说明，保留原证据；现行文档的旧版本由 Git 历史保留。
6. `docs/acceptance/`、本地水点调查/升级文档和实际截图被 Git 忽略，仅在原开发机可用。它们不是发布仓库的必读链接；可发布摘要在 STATUS、docs/09 和 releases/changes 中，不复制敏感样品明细。
7. 跨项目链接依赖同级检出；单仓库检出没有依赖资料时，以对应仓库的记录版本取得，不能把链接存在当作已部署证明。
