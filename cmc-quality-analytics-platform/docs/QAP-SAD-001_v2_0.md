## 2. 目标组件与职责

- 前端延续 React + Ant Design + Vite + TypeScript，继续复用现有图表库；按负责人后续反馈恢复旧看板的操作布局，见 [界面恢复清单](QAP-UI-PARITY-001.md)。图表技术标准演进另行安排。
- FastAPI 分为只读分析、导入校验/确认、审计与受控后台标准化。共享代码可部署一起，但连接池、权限和事务按职责分离。
- 所有分析数据仍放 `cmc_analytics`。dim 归字典，新增 staging 表归候选结果，mart 归不可变结果及消费视图，meta 归文件/导入/审计/血缘。详见 DDM，旧 quality 只作兼容保留。
- 文件服务负责不可变原文件、hash、下载授权和保留策略；文件区不在 Git/前端 public 目录，不暴露原始服务器路径。
- ETL 与 GMP 快照仍由中台建设。QAP 不写共享 LIMS staging、raw 或 MDM，不自行重建权威主数据。
- 相似性/稳定性重用统计函数前必须独立验证；当前混合模型旧回归测试不足以排除组名排序影响。

## 3. MDM 与门户接入（代码已接入，真实配置/门户待验收）

账号、密码和角色只在 MDM 维护；后端不签发自己的令牌，不建本地账号表。前端采用 cmab-hub 的 `cmabSession.ts` 模式，直接使用门户同源 `/mdm/api/v1/auth` 登录/续期/登出，共用会话键、空闲策略和跨标签同步。

后端依总纲模板本地验签，校验签名、exp、type=access，读取 roles/username/full_name。MDM 当前不提供 iss/aud，不擅自要求这两个 claim。`must_change_password=true` 返回 403 并提示先改密码，避免 401 刷新循环。部署要求身份配置完整，否则启动失败；开发开放模式不得开放受控导入。

浏览、上传、确认、更正/撤回、主数据维护及项目/部门可见性分别判定。2026-09-16负责人已确认QC综合（QAP_QC_GENERAL）可查看/导入，QA放行（QAP_QA_RELEASE）仅查看；两个角色已在Mac MDM创建且未分配员工，QAP默认浏览/预览列表已对齐。当前QC仅开放结构预览，正式导入功能未完成；QA角色名不赋予本模块放行审批能力。其他角色不自动获权，项目范围及更正/字典管理权限仍待确认。前端显隐只改善体验，所有动作在后端检查。员工快照来自验证后的令牌，数据库服务账号不代替员工身份。

门户卡片、反向代理路径、前端 base path、API 路由/CORS、401 续期与文件大小限制作为单独接入验收项。最终路径先查 cmab-hub 现有配置再定，本文不声称已接入。

## 4. 查询与导入服务契约

已有路由为 meta/release、stability/options、stability、auth/status、auth/me 及 imports 的 capabilities/templates/preview；稳定性两个POST端点均为只读查询并应用浏览守卫，只接受RD来源。模板下载返回 XLSX，其余保持 `/api/v1/` 和 `{data,meta,errors}` 信封。稳定性实现边界见 [实施记录](QAP-STABILITY-001.md)。当前预览固定 `can_commit=false`、`business_validation=pending`，显示最多200行/1000条问题并返回总数/截断标记，结构通过仍不能确认导入。公开 `/health` 只返回服务存活，数据库连接检查在浏览守卫后的 `/api/v1/meta/database-health`。具体本地配置与边界见 [本机开发说明](QAP-LOCAL-DEV.md)。

下表仍为正式导入/分析目标，不表示对应服务已经实现：

| 服务 | 行为 |
|---|---|
| 查询/分析 | reader 只读当前或指定 dataset，返回 batch_number、单位、规格及未评价原因；不同方法/样品/单位不可自动聚合 |
| 上传 | 保存原文件，登记员工/来源声明/模板，返回 import_batch_id |
| 校验/预览 | 全部问题及行格定位，绑定文件/规则/数据集版本，展示确切新增/替换/撤回清单 |
| 确认 | 权限与预览重新校验，幂等，原子发布；冲突要求重新预览，失败不半入库 |
| 导入历史/下载 | 显示尝试、错误、文件hash、员工、数据集和更正关系；下载独立鉴权和审计 |
| 更正/撤回 | 指定旧结果/观察、理由、目标范围，保留旧版本；不能用文件名 DELETE 替换 |

分析审计走独立 writer；不能给查询账号事实写权限来“顺便记日志”。发布成功事件与数据集切换同事务；失败事件另行持久化。不可变事实与数据集输入清单让旧报告可重现。

## 5. 部署和配置（目标）

| 环境/服务 | 运行方式/端口 |

| Mac PostgreSQL | Docker rd_pg:5432，cmc_analytics 已有数据 |
