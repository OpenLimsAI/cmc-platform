# RD / QC 来源接入记录

2026-09-16，Mac 本机。仅修改应用代码、测试和文档，没有修改数据库结构、权限或数据，没有推送或访问 Linux。

## 已实现

两页筛选区首项为“数据来源”：`RD_LIMS（研发）`、`QC_LIMS（历史记录）`。切换时清空项目、全部下游条件和图表，取消旧请求；项目与筛选项按所选来源重查。放行缓存保存来源，旧 `ALL` 或非法来源缓存整体清空。结果条件显示来源，不将两种来源混合统计。

| 选项 | 当前实际查询 | 不代表 |
|---|---|---|
| RD | `cmc_analytics.staging.stg_sample/stg_test/stg_result`，`source_system=rd_samplemanager` | 已完成单位、规格或统计业务验收 |
| QC | 同三张共享表，`source_system=gmp_labvantage` | 完整/最新/已批准 GMP 数据、新 QC 原生五表、旧 Excel 导入 |

现有 API `meta/projects/lines/attributes/coverage` 及放行 options 增加可选 `data_source=RD|QC`，缺省 RD。放行/稳定性 POST 均接受单一来源。原放行请求曾声明 `ALL`，本项目页面没有使用；本轮明确拒绝（422），避免混用统计/规格。将来发布时须核对未登记的外部调用者，不能悄悄把 ALL 当成 RD。

QC 类别只接受旧 staging 明确值“常规放行”“稳定性”；其他值进入 Unknown，不套用 RD 关键词推断。QC 保留原检测项名及数值，不用 RD 指标别名和百分比换算。类别只决定查看页面，不代表批准状态。

QC 放行按原检测项、方法、样品、类别、单位和来源产线标签分面，散点保留重复观察；有单位时展示描述统计，缺单位只显示原值。单观察的样本 SD 为空；不调用 RD 规格、不计算能力指数。QC 稳定性复用已实现的来源隔离、时间/单位分面和原始明细；缺时间不画点，缺单位不做统计或拟合。

现有七类指标组合继续用于准确匹配；QC 指标尚未建立相应字典，页面说明应从“质量属性”选择或留空查看全部，不能为了启用按钮猜测映射。

## 本机复核与局限

- 先前本日计数：共享 `stg_result` 有 3,339 条 QC 来源记录。本轮经三表关联、项目非空、结果数值非空筛选，实际可读 2,161 条、21 个项目，其中放行 2,004、稳定性 157；稳定性 154 条可画点、3 条缺时间点。不要把 3,339 当成全部可分析观察数。
- 只读目录核对：当前 Mac 无 `staging.stg_lv_*` 对象。相邻 `qc-lims-etl` 的实际代码已面向 QC 原生五表，其文档标明旧三表映射有损；不能据此宣称新 QC 链已部署或已验收。
- 来源中的项目、产线/组别标签、时间点等仍需业务核对；不将它们重新解释为已核验的正式项目/产线、研究或储存条件。没有检查或恢复 raw/GMP 连接。
- 当前应用连接仍为 `lims_admin`，会话 `transaction_read_only=on`，不能替代真实最小权限 reader。本轮未更换账号或授权。
- `quality.quality_data`、`quality.import_history` 存在，但当前账号对 quality schema 无 USAGE、对两表无 SELECT。本轮没有绕过权限读取。旧 Streamlit Excel 导入代码把记录标为 `QC_LIMS`，这个文字标签本身不证明记录来自 QC ETL 或已获批准。
