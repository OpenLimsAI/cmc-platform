# 1. 设计原则与理念

## 1.1 整体设计理念

CMAB MDM Portal 是面向研发与质量人员的内部工具型系统，UI 设计核心理念：

### 1.1.1 工业级而非消费级

- 信息密度高于美观度：研发人员每天处理大量数据，过度留白会浪费屏幕空间

- 功能可发现性优先于视觉风格：所有功能必须 2 步以内可达

- 数据准确性高于动画效果：状态、版本、时间戳必须清晰可见

- 效率工具优先：键盘快捷键、批量操作、高级筛选不可或缺

### 1.1.2 一致性高于创造性

- 严格遵循 Ant Design 5 设计规范，不做样式定制

- 跨模块（SRS/PRS/ARS/MM）使用统一布局、组件、交互

- 相同语义使用相同视觉表达（如所有「草稿」状态用同一灰色 Tag）

- 用户从一个模块迁移到另一个模块零学习成本

### 1.1.3 渐进信息披露

- 列表 → 详情 → 编辑：每层只展示当前任务必要信息

- 详情页用 Tab 分组（基本信息 / 蛋白属性 / 标识符 / 关联 / 审计）

- 复杂表单分步（Steps），降低单屏认知负担

- 默认隐藏高级选项，常用 80% 优先呈现

### 1.1.4 错误友好

- 行内校验：用户填表时实时给出错误提示

- 不可逆或高风险操作必须二次确认，例如 Substance 弃用、Asset 终止、软删除等。Substance 合并属于 Phase 5 数据治理工具，Phase 1–3 不显示合并入口，不纳入当前 UAT 范围。

- 电子签名前展示完整快照，签名后展示哈希值

- 所有错误消息中文友好，避免技术术语堆砌

## 1.2 设计系统

### 1.2.1 色彩系统

严格遵循 Ant Design 5 内置色彩，避免随意自定义：

| **用途** | **色值** | **使用场景** |
|----|----|----|
| 主色（Primary） | \#1F4E79 | 顶部导航、主按钮、链接、强调标识 |
| 次主色（Secondary） | \#2E75B6 | 次要操作、副链接、辅助强调 |
| 成功（Success） | \#52C41A | 状态：active / approved / completed |
| 警告（Warning） | \#FAAD14 | 状态：on_hold / pending / restricted |
| 错误（Error） | \#FF4D4F | 状态：terminated / rejected / locked，删除按钮 |
| 信息（Info） | \#1677FF | 提示、信息标签 |
| 默认（Default） | \#8C8C8C | 状态：draft / deprecated / obsoleted |
| 背景灰 | \#F5F5F5 | 页面背景、卡片间隔 |
| 边框灰 | \#D9D9D9 | 分割线、表格边框 |
| 文字主色 | \#262626 | 正文文字 |
| 文字次色 | \#595959 | 次要文字、标签 |
| 禁用色 | \#BFBFBF | 禁用文字、占位符 |

### 1.2.2 状态色映射

各域的状态使用统一色彩语言：

| **状态**  | **颜色** | **Substance** | **Project** | Asset.status | **Material**     |
|-----------|----------|---------------|-------------|--------------|------------------|
| 草稿      | 灰       | draft         | proposed    | —            | —                |
| 注册中    | 蓝       | registered    | initiated   | —            | —                |
| 活跃      | 绿       | active        | active      | active       | in_stock/in_use  |
| 暂停      | 黄       | —             | on_hold     | on_hold      | quarantine       |
| 受限      | 黄       | restricted    | —           | —            | —                |
| 完成      | 绿       | —             | completed   | —            | —                |
| 弃用/终止 | 红       | obsoleted     | terminated  | terminated   | rejected/expired |

### 1.2.3 字体与间距

- 字体：系统默认无衬线（中文 PingFang SC / Microsoft YaHei，英文 system-ui）

- 正文：14px / 行高 1.5

- 标题：H1 24px、H2 20px、H3 16px、H4 14px（粗体）

- 辅助文字：12px

- 间距遵循 Ant Design 8px grid：4 / 8 / 12 / 16 / 24 / 32 / 48

### 1.2.4 图标

- 统一使用 Ant Design Icons（@ant-design/icons）

- 特殊图标使用 Lucide React 补充（一致风格）

- 严禁混用多个图标库，禁用 emoji 作为功能图标

- 图标大小：行内 14px、按钮内 16px、空状态 64px

## 3.2 Header 设计

### 3.2.1 Logo 区

- 左上角，宽 240px，与侧边栏对齐

- 内容：CMAB 公司 logo + 文字「CMAB MDM Portal」

- 点击返回 /dashboard

### 3.2.2 全局搜索

- 位置：Header 中央，宽 480px

- Placeholder：「搜索物质 / 项目 / 资产（V1.1：Phase 1-3 支持 3 类，物料推迟到 Phase 4）... (Ctrl+K)」

- 输入后实时下拉建议（debounce 300ms）

- 结果按类型分组（V1.1：物质 / 项目 / 资产；物料随 Phase 4 MM 域接入），每组最多 5 条

- 点击建议项跳转详情页；按 Enter 跳转完整搜索结果页

- 通知图标（铃铛）：未读数红色徽标，点击展示通知列表（待审批 / 系统消息）

## 3.3 Sidebar 设计

## 5.2 筛选区规范

### 5.2.1 筛选层级

- 常用筛选（默认显示）：3-5 个最高频字段，单行展示

- 更多筛选（折叠）：点击展开抽屉式高级筛选，包含日期范围、关联实体、保密等级等

- 关键词搜索：始终显示，对应 ?q= 全文搜索

- 筛选条件用 URL 参数同步，刷新页面/分享链接保持状态

### 5.2.2 筛选交互

- 修改筛选项后不立即触发查询，需点击「搜索」按钮

- Enter 键在任意字段触发搜索

- 筛选条件外用蓝色 Tag 显示，可单击 ✕ 删除

- 重置按钮清空所有筛选条件

## 5.3 数据表格规范

### 5.3.1 列设计

- 固定列：第一列 checkbox（批量选择），最后一列操作（···）

- 默认列：实体编码、关键属性、状态、关联计数、更新时间

- 用户可通过「列设置」自定义显示列，存到 localStorage

- 编码列点击跳转详情页（蓝色链接样式）

- 状态列使用色彩 Tag（详见 1.2.2 状态色映射）

- 数字列右对齐，文本列左对齐，时间列居中

### 5.3.2 排序

- 默认排序：updated_at 倒序

- 点击表头切换升降序（仅可排序列显示箭头）

- 可排序列：编码、首选名称、状态、创建时间、更新时间

### 5.3.3 行操作

最后一列···按钮展开下拉菜单：

- 查看详情（在新 Tab 打开）

- 编辑（跳转编辑页）

- 复制编码（复制到剪贴板）

- 查看审计日志

- 软删除（红色，需二次确认）

### 5.3.4 批量操作

- 勾选多行后，工具栏「批量操作」按钮可用

- 可用操作：批量导出、批量软删除、批量更改状态（如批量激活草稿）

- 批量操作执行前显示确认对话框，列出受影响的所有记录

- 批量结果以列表形式展示（成功 X 条，失败 Y 条，可查看错误详情）

## 5.4 空状态与加载状态

### 5.4.1 空状态

- 无数据：图标 + 提示语 + 主操作按钮（如「创建第一个物质」）

- 筛选无结果：图标 + 「未找到匹配的物质」 + 「清除筛选」按钮

- 加载中：表格使用 Skeleton 占位，避免页面跳动

- 加载失败：错误图标 + 错误消息 + 「重试」按钮

### 5.4.2 性能优化

- 分页默认 20 条，可选 10/20/50/100

- 超过 100 条/页时使用虚拟滚动（Ant Design Virtual Table）

- 筛选条件防抖：关键词输入 500ms 后才触发搜索建议

8.5 业务规则态禁用（V1.1 新增）

① ARS 禁用以 asset.status=terminated 为唯一判定依据——所有写入按钮置 disabled + tooltip 提示"资产已终止，禁止变更绑定关系"

# 9. 关键交互模式

## 9.1 表单设计

### 9.1.1 字段标注

- 必填字段：标签后用红色 \*（如「首选名称 \*」）

- 条件必填：在 placeholder 中说明「如选择 ADC 类型，需关联抗体」

- 不可修改字段：禁用状态 + 提示「创建后不可修改」

- 帮助文本：字段下方灰色小字，简短说明

- 校验失败：红色边框 + 字段下方红色错误消息

### 9.1.2 校验时机

- 失焦校验：单字段校验（格式、长度）

- 提交校验：跨字段校验（依赖关系、唯一性）

- 异步校验：编码唯一性、序列同一性

- 校验失败时滚动到第一个错误字段并聚焦

### 9.1.3 自动保存草稿

- 创建表单：每 30 秒自动保存到 IndexedDB（仅前端，不入数据库）

- 用户离开页面时提示：当前草稿将保留，下次进入恢复

- 提交成功后清除草稿

- 不适用于编辑表单（避免覆盖他人修改）

9.2.1 状态变更通用交互模式（V1.1 扩充）

所有三域（SRS / PRS / ARS）状态流转 UI 统一规范：

1\. 触发方式：详情页右上操作菜单，按状态机派发当前可用动词命令

2\. 公共必填字段：变更原因（\>=5 字校验，前后端双校验）

3\. 签名字段按动作分（不是所有状态变更都签）——仅关键不可逆动作强制电子签名：

SRS substance（4 个签字动作）：approve / activate / deprecate / obsolete

PRS project（3 个签字动作）：approve / complete / terminate

ARS asset（1 个签字动作）：terminate

其他动作（hold / resume / start 等）不要求电子签名

4\. 二次确认弹窗：仅签字动作触发；可逆动作不弹

5\. 401 响应 meta.error.type 分流：仅电子签名 / 身份再验证场景涉及（详见 §9.6）

6\. 提交成功后：刷新详情页 + Toast 通知 + 状态历史 Tab 追加新条目

## 9.3 长操作反馈

- \< 100ms：无需反馈

- 100ms - 1s：按钮 loading 态

- 1s - 5s：全局 loading 进度条（顶部）

- \> 5s：进度对话框 + 取消按钮（如批量操作、导出）

- \> 30s：异步任务模式（提交后跳转到任务中心，完成后通知）

| 错误     | ✕ 红     | 校验失败：首选名称必填         |
| 警告     | ⚠ 黄     | 您离开当前页面，编辑内容将丢失 |
| 信息     | ⓘ 蓝     | 审核任务已分配给您             |

## 9.5 锁与并发

- 详情页加载时显示当前编辑者：右上角「清城正在编辑（5 分钟前）」

- 提交时检查 version：不一致时弹窗「该资源已被他人修改，请刷新后重试」

- 不实现强制锁，仅显示软提示（避免锁孤儿问题）

9.6 401 响应 meta.error.type 分流（axios 拦截器约定）（V1.1 新增）

背景：电子签名密码错（业务身份再验证）与 JWT 过期（会话失效）都返回 401，但语义不同。

约定：前端 api/client.ts 的 axios response 拦截器按 API 响应中的 meta.error.type 字段分流：

· meta.error.type=token_expired 或 token_invalid → 清 localStorage token + redirect 到 /login?redirect=...

· meta.error.type=signature_invalid → 保留 token，仅在调用方对话框内显示"密码错误，请重新输入"，不跳登录

· 无 meta.error.type 字段或未知值 → 按 HTTP 状态码和调用上下文兜底处理；401 默认按会话失效处理（向后兼容）

# 10. 响应式与可访问性

## 10.1 屏幕尺寸支持

CMAB MDM Portal 主要面向桌面办公场景，但需保证关键功能在平板可用：

| **设备** | **宽度范围** | **支持级别** | **适配策略** |
|----|----|----|----|
| 大桌面 | ≥ 1920px | 完整 | 侧边栏 240px + 内容区充分利用 |
| 桌面 | 1440-1919px | 完整 | 侧边栏 240px + 适当紧凑 |

| 手机 | \< 768px | 仅查询 | 仅支持登录、查询；编辑提示用桌面 |

## 10.2 可访问性 (a11y)

- Ant Design 5 内置 ARIA 属性，原生支持屏幕阅读器

- 所有交互元素必须可键盘操作（Tab 导航、Enter 触发）

- 表单标签必须与控件正确关联（label htmlFor）

- 错误消息使用 role=alert

- 色彩对比度满足 WCAG 2.1 AA 标准

- 不依赖颜色单独传递信息（状态用图标 + 文字 + 颜色）

# 11. 国际化与本地化

## 11.1 语言支持

- 第一版：仅简体中文 (zh-CN)

- Phase 5+：英文 (en-US)，主要面向 FDA/EMA 申报场景

- 使用 react-i18next，文案集中在 src/locales/{lang}.json

- Ant Design ConfigProvider 统一控制日期、表格、确认框语言

## 11.2 文案规范

- 中文：使用 GB/T 文档表述风格，避免口语化

- 术语：与本系列设计文档一致（参考 ARCH-MDM-001 第 2 章）

- 按钮：动词开头（创建 / 编辑 / 删除 / 取消 / 提交）

- 提示语：以用户为中心（「您」而非「用户」）

- 错误消息：简洁 + 可操作（「网络异常，请重试」 而非 「Error 500」）

## 11.3 时区

- 数据库存储 UTC，前端按用户偏好（默认 Asia/Shanghai）展示

- 用户可在偏好设置中切换时区

- 审计日志可选择「按 UTC 显示」以便核对原始记录

## 11.4 数字与日期格式

- 数字：千分位逗号分隔（1,234,567）

- 货币：¥ 5,000,000.00

- 日期：YYYY-MM-DD（2026-05-11）

- 时间：YYYY-MM-DD HH:mm（2026-05-11 14:25）

- 相对时间：2 小时前 / 昨天 18:30 / 3 天前 / 上个月
