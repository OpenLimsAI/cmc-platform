# 首次 SSO-only 管理员初始化

仅适用于已授权的 Linux 部署运维流程和已证明新建的独立 MDM 数据库。不能在未知/共享库尝试，不能通过 HTTP、原生密码登录或客户端角色猜测获得此能力。

## 输入与执行边界

`python -m app.scripts.sso_bootstrap --plan /run/approved-bootstrap.json --secret-output-dir /run/bootstrap` 只校验计划结构，不初始化用户。增加 `--apply` 才执行；必须先取得该次角色、身份映射及初始签名凭据生成/交付的明确授权。该参数本身不是授权凭证。

计划为0600、运行UID所有的普通文件；输出目录必须预先建立，0700、同UID所有、非符号链接。应由只执行一次的受控容器挂载交付目录，普通Web进程不持有交付文件目录。工具接受一至两个明确管理员，实际数量与名单严格遵循当次授权，角色固定为MDM SYS_ADMIN；不能借此改PM/IdP角色。

计划字段：

- `database_host`、`database_port`、`database`：必须与运行时异步数据库URL逐项一致；bootstrap拒绝所有连接查询参数，避免hostaddr/service等覆盖目标。本文不假定实际部署容器名。
- `issuer`、`organization`：必须精确等于部署配置。环境要求OIDC开启、native关闭；不改变原生登录、refresh或Bearer拒绝策略。
- `operator_subject`：本次明确批准的管理员之一，作为旧映射表 `created_by` 外键对应的授权负责人；不是伪造此人的SSO登录。
- `operator_ref`、`reason`：非空白运维执行/授权引用与原因，不能含秘密。
- `accounts`：一至两份唯一的 `username`、不可变 `subject`、有效联系 `email`、`full_name`。必须从已核实来源取得，不填假地址、不按同名/邮箱自动绑定。

具体计划包含实际个人资料，应留在服务器受限配置，不提交仓库或验收截图。工具不接受密码参数，不读取Casdoor密码或导入其角色，不请求外部身份接口。

## 创建、失败和重试

仅允许迁移所需的角色/权限/配置基线；已有身份或核心业务实体会拒绝。事务advisory lock串行化初始化；权限目录初始化不创建演示用户、物质或项目。用户数字ID由数据库分配，每个subject与数字ID唯一绑定。

每名用户生成独立随机签名初始密码，24小时有效、强制首次改密。密码只写 `<username>.initial-password` 的新0600文件，不覆盖旧文件、不进stdout/日志/审计/计划。数据库只存哈希和历史。

审计的实际操作人是 `deployment.cli`、`user_id=null`，额外记录执行UID、运维引用、明确授权的subject/数字用户及固定角色。不会生成LOGIN历史或电子签名来冒充本人操作。

相同计划/同一目录的成功重试返回 `idempotent`，不会再次发密码、改用户密码或恢复已撤销权限。不同计划或映射冲突拒绝。COMMIT发出前的失败回滚事务，只删除本进程创建、inode匹配的文件；COMMIT发出后的错误可能结果不明，保留交付文件并先检查数据库标记，不能盲目重试或删除唯一交付副本。

## 首次进入和后续密码管理

管理员仅通过Casdoor登录。首次改密前只能走已有受限改密闭环，不能审批或读写业务；原签名密码/强度/历史/期限校验保留。修改密码会使旧MDM会话失效，之后通过Casdoor重新进入。SSO-only文案明确这是签名密码，不能用于登录，也不是Casdoor密码。

真实账号的最终密码由本人修改，不能由自动化代填或写入聊天。运维确认本人改密后，仅移除对应已知交付文件；不要删除未知文件。系统原生恢复管理员不属于本方案。
