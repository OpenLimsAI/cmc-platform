## 实际发现并修复的问题

1. 前端在途响应曾让明确本地退出立即重入 SSO（截图19，red）。补充 auth epoch、退出意图及路由原因保留后真实复验通过。
2. 官方 Casdoor 3.152.0 在 PostgreSQL 裸 `user` 列条件下查询/过期零行，返回 ok 却未撤销旧门户会话。固定官方修复提交 `edfbb9323be4e6ac3a507f08d49fae025431c52f` 的首个正式版本3.154.4重验通过。应用增加注销前后 introspection，拒绝把 no-op 当成功。细节和固定镜像见 [provider-compatibility.md](provider-compatibility.md)。
3. IdP已删服务端会话后，其浏览器 GET logout 返回 JSON（截图34，red）；应用改成确认成功后固定返回自己登录页。
4. 前端原来只接受 IdP logout URL，误拒该固定本地地址（截图48，red）；现在只接受与预期本应用地址逐字相等的本地返回，额外参数/重复query/凭据/不同主机仍拒绝。最终前端真实复验通过。

统一退出作用于该主体已有应用会话，非单设备范围；原生密码会话与未接入应用不在范围。IdP旧浏览器 Cookie 物理字节可能仍残留，但服务端会话已无效，不能再静默登录；不宣称物理擦除 Cookie。
