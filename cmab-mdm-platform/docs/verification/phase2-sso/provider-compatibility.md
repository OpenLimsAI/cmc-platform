# 本阶段 Casdoor 部署契约与真实退出缺陷

本文件记录本机隔离验收所需前提，不修改现有或正式身份平台。

## 已验证版本

本轮真实 PostgreSQL 验收最终采用官方 **Casdoor 3.154.4**，镜像固定为
`casbin/casdoor@sha256:95c7be68fb98daf2ec74a10c9f785af1ef75e8fef6dd4aad455a899e651e87e2`。
这不是对所有更新版本、数据库或部署方式的兼容声明。

旧官方 3.152.0 的 `object/token.go` 在按用户查询/过期令牌时使用裸 `user` 列名；
PostgreSQL 将其解释为当前数据库用户，真实退出返回 ok 却命中零条令牌，后续门户仍可访问。
官方修复提交为 [edfbb9323be4e6ac3a507f08d49fae025431c52f](https://github.com/casdoor/casdoor/commit/edfbb9323be4e6ac3a507f08d49fae025431c52f)，
首次包含该修复的正式版本为 3.154.4。应用额外检查注销前 active、对应 client/sub 和注销后严格 inactive；
不把 HTTP 200 或 `status=ok` 单独当作全局注销成功。

3.154.4 的真实签名通知在本轮将 MDM/PM/门户旧会话撤销，后续实际请求拒绝。
用户禁用也通过标准管理接口在本轮测试身份上真实验证，恢复后旧会话不复活。
没有手工过期 token 表、替换数据库类型或部署自定义 Casdoor 补丁。

## 最小配置及权限边界

- MDM 独立登录客户端和单独 PM 用户委托客户端；门户、PM 各自独立客户端。
- 固定 issuer、签名公钥、audience、授权码 PKCE/state/nonce、只允许注册本应用回调。
- 应用仅持有自己客户端和对应当前用户短期令牌，不持有 IdP 管理密钥，不枚举组织用户。
- 本实现仍要求固定组织与两个账号状态字段本人可见的显式配置门槛；状态读取只针对已验证 subject。
  测试组织只开放 `isForbidden`/`isDeleted` 的 Self 查看，修改仍为管理员。
  Casdoor 3.154.4 本身也在标准 introspection 中反映用户有效性；本轮保留额外本人状态核验作为已测试契约。
- IdP 无法访问、状态不可确认或响应不符合固定主体契约时拒绝业务访问，无无限缓存或静默降级。
- 两应用的业务角色继续分别管理；PM 的 cmc_lead 不会获得 MDM 管理权限。
- 功能默认关闭；正式启用、真实用户映射、正式凭据配置和数据库迁移需独立部署授权与验证。

## 注销范围和失败结果

“仅退出 MDM”撤销本应用会话，不撤销门户、PM 或 IdP 会话；重新 SSO 必须由用户主动发起。
“退出统一身份及各应用”调用本人 `logoutAll`，以有效签名通知和后续在线核验令该主体已有应用会话失效，
属于该用户的现有会话范围，并非只限当前设备。原生 MDM 密码会话和未接入应用不在统一注销范围。

确认上游注销后直接返回固定本应用登录页。Casdoor 的旧浏览器会话 Cookie 物理字节可能仍存在，
但服务端会话已经撤销，不能再静默登录；不通过 URL 传递 token 或共享跨应用 Cookie。
若远端注销未确认，本地仍退出并明确提示“门户或 PM 会话可能仍有效”，不会声称全局成功。

## 迁移和回退

本轮仅对证明全新、空表、tmpfs、无宿主数据库端口的三个测试库执行迁移。
官方 IdP 正常 Sync2 新增的两个可空字段、业务迁移 0067/0068 与 PM 007 均保留在版本证据中。
正式或未知数据库未执行升级。

应用代码回退可先关闭新功能并恢复明确允许的原生入口；不得自动拆除已有项目关联或身份审计。
非空身份/回执迁移降级保护会拒绝删除数据。旧 IdP 容器若带重复初始化设置不能直接启动覆盖现库；
需要恢复时应保留正确 `initDataNewOnly` 和完整配置，并先验证目标及备份。
