# MDM 统一身份与 PM 创建界面

2026-10-26。本阶段前端使用独立 HttpOnly cookie 会话，OIDC 访问令牌、ID令牌和 PM 委托令牌不进入 JavaScript、URL 或 localStorage。`authMode=oidc` 仅记录已由服务端会话端点返回的用户；没有用假 JWT 维持路由。服务端权限仍为权威。

## 登录、恢复和退出

应用先读取 `/auth/oidc/config`，启用时尝试恢复 `/auth/oidc/session`，完成后才渲染受保护路由。OIDC关闭时不查询SSO会话，原生JWT及历史共享键保持兼容；配置或会话网络故障明确阻断，不静默猜测认证配置。SSO成功会清除本浏览器遗留的原生bearer，避免两种身份混用，因此仅在明确开启SSO的环境采用新模式。

统一登录和用户委托分别导航 `/auth/oidc/login`、`/auth/oidc/pm-login`。回调落到 `/mdm/auth-complete?return_to=...`，没有令牌参数。回跳只接受应用内路径，拒绝站外、反斜杠、控制符、点路径、认证端点、凭据参数及fragment。错误、退出和过期页不自动循环发起SSO。`/mdm/login?native=1` 是明确原生恢复入口，仍受服务端 `native_login_enabled` 控制；此入口不先探测失效的SSO cookie。

OIDC模式每30秒及页面重新可见时核对服务端会话并替换当前MDM权限，不调用原生JWT refresh。空闲退出仅处理MDM本身。菜单区分“仅退出MDM”和“退出统一身份及各应用”，全局注销需要服务端确认；部分失败只说明本地成功，不能把清前端状态说成全局完成。全局范围不包含未接入应用或独立原生会话。

全局注销成功且服务端提供`logout_url`时，如果该值与本应用固定完整登录地址逐字完全相等，使用本地路由返回登录，不打开外部地址。其他地址仍仅接受Casdoor公开`/api/logout`：HTTPS或本机回环HTTP、无userinfo/fragment、仅client_id及固定同源`/mdm/login?reason=logout`返回地址，不允许token或id_token_hint。仅退出MDM、全局未成功或无该地址时均返回本地登录。服务端warning以文本弹窗实际展示，用户确认后才清本地状态并继续导航；部分失败不能先跳走而丢掉提示。

电子签名业务调用未改；SSO时界面明确提示“MDM签名密码（非Casdoor密码）”，仍需既有数字用户原来的MDM密码再次认证。

## 创建并关联

原人工关联保留。新增创建入口仅在MDM有 `project:update` 权限并已有SSO会话时展示授权流程，不用全局只读核验身份代替创建用户。产品类型/阶段/负责人选项从PM权威接口经MDM后端取得；编号、名称、起止阶段、负责人和计划日期均显式填写，不猜同名用户、不默认计划/预算/团队。

创建请求UUID在同一表单提交与失败重试间保持不变；已有服务器操作ID优先，页面重新进入先查询操作，不能因响应丢失发起另一项目。UI展示pending/in_progress/retryable_error/remote_created/linked/reconciliation_required，仅服务器确认linked才称完成。重试按钮只在服务器 `can_retry` 时出现，使用保存的请求与字段；业务拒绝或本地冲突需处理原请求，不能隐式改参。
