## 二、日常标准流程

**新买了一种试剂（MDM 里还没有）：**
1. 打开 MDM（15173）→ 物料 → 新建物料，填编码/名称/厂家，保存；
2. 回 LabOps（5110）→ 入库登记 → 输入编码 → 信息自动带出 → 填批号数量入库。

**新买了一台仪器：**
1. 打开 MDM → 设备 → 新建设备（编码可留空自动生成）；
2. 回 LabOps → 设备台账 → 新增设备(从 MDM 引用) → 搜出来选中 → 填房间和负责人。

**忘了先去 MDM？** 没关系——LabOps 查不到时会弹出"去 MDM 登记"按钮，点过去登记完回来重查就行，编码都帮你填好。

**给新同事开账号 / 分配权限：** 在 MDM → 系统管理 → 用户管理。角色含义：
- `CMC_WAREHOUSE_ADMIN` = 库管员（能做物料出入库和登记物料）
- `CMC_EQUIPMENT_ADMIN` = 设备管理员（能管设备台账和校验维护）
- `SYS_ADMIN` = 全权限
- 不给角色 = 只能查询

## 三、出问题三板斧

```bash
# 1) 看服务是否活着(应该都是 active)
systemctl is-active cmab-backend cmc-backend nginx

# 2) 重启(网页打不开/报错时先试这个,需要 sudo)
sudo systemctl restart cmab-backend cmc-backend

# 3) 看报错日志(最近 50 行)
journalctl -u cmc-backend -n 50 --no-pager    # LabOps 后端
journalctl -u cmab-backend -n 50 --no-pager   # MDM 后端
```

常见情况速查：

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 登录提示"认证服务不可用" | MDM 后端挂了 | `sudo systemctl restart cmab-backend` |
| 页面全白/打不开 | nginx 或前端构建问题 | `sudo systemctl restart nginx`；不行再按第四节重建前端 |
| 操作报 500 | LabOps 后端问题 | 看 `journalctl -u cmc-backend`，把报错发给 Claude |
| 服务器重启后全挂 | 服务没设自启 | 两个后端都已 `enabled`，正常会自起；不行就执行第 2 板斧 |

## 四、以后怎么升级新版本

以后代码更新（GitHub 上有新提交）时，登录服务器整块粘贴：

```bash
# === LabOps 升级 ===
cd /opt/cmc-labops && git pull
backend/.venv/bin/pip install -q -r backend/requirements.txt
cd frontend-react && npm install --silent && npm run build && cd ..
sudo systemctl restart cmc-backend

# === MDM 升级(如果 MDM 也有更新) ===
cd /opt/cmab-mdm-platform && git pull
backend/.venv/bin/pip install -q -r backend/requirements.txt 2>/dev/null
backend/.venv/bin/alembic -c backend/alembic.ini upgrade head 2>/dev/null || (cd backend && .venv/bin/alembic upgrade head)
cd frontend && npm install --silent && npm run build && cd ..
sudo systemctl restart cmab-backend

# === 验证 ===
curl -s http://127.0.0.1:8010/health; echo ""
systemctl is-active cmab-backend cmc-backend
```

前端是静态文件，构建完立即生效，不用重启 nginx。
