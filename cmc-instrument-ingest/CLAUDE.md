## 这是什么项目

`cmc-instrument-ingest` —— **小仪器原始数据的备份归档中心**（定位于 2026-07-15 确认）。

**本项目只做一件事：Stage 1 —— 从仪器侧只读拉取数据、SHA256 校验、归档到 NAS。不解析业务字段、不入库。**
已接入两台仪器：**FLEX2**（`flex2/`）与 **Vi-CELL XR**（`vicell/`）；Biacore 待收编。
每台一个平级目录，**不做提前抽象**——第三台来了再加。
与仪器无关的通用规范（命名 / 账号 / 采集策略分类 / 校验 / 时间戳 / 告警心跳 / 接入清单）
统一放 **`docs/INGEST-STANDARD.md`**，新增仪器照它办，别现想。

**ETL 不在本项目。** 每台仪器的解析入库各自独立成 repo（Nova → `rd-nova-etl` 已建，
Vi-CELL → `rd-vicell-etl` 已有），从 NAS 读归档 → 解析 → 入 `cmc_rd`，
和 `rd-lucullus-etl` 的做法完全一致。

**两阶段解耦，这是架构的核心，物理上拆成两个 repo：**

```
FLEX2 共享（只读挂载）
    ↓  Stage 1（本项目 flex2/flex2_ingest.py）：复制 + SHA256 校验，不解析业务字段
NAS 原始归档（底本，永久保留）
    ↓  Stage 2（独立 repo rd-nova-etl，**已建成**）：解析 + 入库，只读 NAS，绝不回连 FLEX2
cmc_rd → cmc_analytics
```

**为什么必须拆开**：归档是记录保存义务，ETL 是分析，两者验证范围不同；
合并后改一次 ETL schema 就要重新验证整条归档链路。且 ETL 挂掉时归档必须照常跑——数据先落袋为安。
拆成两个 repo 让这道边界更硬。

### ⚠️ 本项目对外提供的共用组件：告警出口（改之前先看这里）

数据上与下游 ETL 零耦合，但**运维告警**是共用的——本项目提供统一告警出口，
三个仓库共用，免得各带一份脚本然后慢慢漂移：

| 提供 | `tools/ingest-alert.sh` + `tools/deploy/instrument-alert@.service` |
|---|---|
| **使用方（改动前必须盘点）** | 本项目三个采集单元；**`rd-vicell-etl`** 的 `vicell-etl.service`；**`rd-nova-etl`** 的 `nova-etl.service`（后两者通过 `OnFailure=instrument-alert@%n.service` 引用） |

**动这两个文件（改名/挪位置/改路径）前，必须同时改上面两个下游仓库**，
否则它们的 `OnFailure` 会静默失效——systemd 只留一行
`Failed to enqueue OnFailure= job, ignoring: Unit ... not found.`，
主服务照常失败、告警一条不发，没人会发现。这与总纲「改共用表前先盘点全部使用方」
是同一条铁律（2026-08-04 LIMS 断流事故的教训）。

外呼开关：`/etc/instrument-ingest/alert.env` 的 `INGEST_ALERT_WEBHOOK`，
留空则只写 journald（`journalctl -t instrument-alert`）。样例见 `tools/alert.env.example`。

### ⚠️ 采集时刻与下游 ETL 是硬耦合的（改时刻必须两边一起改）

采集排 `11:45` / `16:00`，下游 `rd-vicell-etl` / `rd-nova-etl` 固定滞后 20 分钟排
`12:05` / `16:20`，靠这个间隔保证「先备份、后入库」。所以：

- 采集 timer 的 `RandomizedDelaySec` **必须为 0**，一加随机延迟 ETL 就可能跑到备份前面；
- **改采集时刻 = 同时改那两个仓库的 timer**，只改一边的后果是当天数据入不了库，
  而且不报错、无人察觉（同总纲「改共用组件前先盘点全部使用方」）。

## 铁律（不可违反，违反了不是 bug 是事故）

1. **解析 CSV 必须按列名映射，禁止按列位置。**
   实测：逐次导出与月度导出的**列顺序不同**（`PO2@Temp`/`PCO2@Temp` 互换、
   `pH / Gas Flow Time`/`Chemistry Flow Time` 互换）。按位置解析会**静默调包数值**——
   不报错、数值都在合理范围、看不出来。
   列集合发生变化时必须**告警**，不许静默吞掉。
   **2026-07-16 实机发现更严重**：月度文件**同一文件内就混着多种行宽**——某些样品未测的通道
   不留空占位、直接省略，使该行变短（实测 2026-July 一个文件里有 41/38/35/33 四种行宽，
   且**套餐化、非随机**）。所以连"按列名映射"都要先**按行宽判套餐、再对回列名**。
   归档层（Stage 1）对此**只告警、不拒收**（见铁律 5）；套餐解析是 Stage 2 的活。
   **治本**：推动 Nova/操作员把导出改成"未测通道也留空占位"（见待办）。
   **🟢 2026-07-23 已从仪器全量重新导出，错位问题终结**：重新导出会「留空占位」而非省略，
   810 条错位行 100% 救回，**数值一律以重新导出的文件为准**（见 §10）。
   下面三条是历史结论，解析老的月度文件时仍需知道（`docs/source-survey-flex2.md` §8）：
   ① 试剂批号**没丢**——尾部结构 100% 恒定，批号永远在 `[w-8..w-5]`（w=行宽），可从末尾锚定；
   ② 省略是**多处分段发生**的，短行中段数值无法从月度文件自身还原，
      **必须用逐次文件补**（覆盖 99.4%），补不到的置空并标记，**不许猜**；
   ③ **表头列数本身也会变**（2025-12 / 2026-02 表头只有 38 列，却有 41 列的数据行），
      所以 ETL 必须用**固定 41 列标准表头**，**不能信任文件自带的表头行**。

2. **源挂载点永远 `ro`。** 脚本启动时自验：能写入就立即中止。
   这是保护仪器数据的第一道锁，任何情况下不得移除。

3. **`.dbb` 只归档，不解析，不尝试破解。**
   实测是 7z 容器 + **AES 加密**（`LZMA2 + 7zAES`），密码在 Nova 手里。
   它的定位是**灾备保险**，不是数据源。不要写解压代码。

4. **不做"样品数据陈旧"告警。**
   实测这台仪器会连续停机 2–3 周（2026-01-23→02-05 空 13 天；02-10→03-03 空 21 天）。
   用它告警只会天天误报，最后没人看告警——那才是真正的失效。
   健康信号用 **Database 备份的新鲜度**（每晚 23:30 固定跑，与做不做样品无关）。

5. **校验不过就不归档——但"坏"特指损坏，不是"结构复杂"。**
   宁可告警缺一天，也不能把**损坏**数据（非 UTF-8、CSV 无法解析、空文件）写进"底本"。
   但"同一文件多种行宽 / 带 BOM"这类**完好但结构复杂**的数据**必须照常归档（只告警）**，
   否则会把**可救的主数据源**丢掉——那才是真正的失效。（2026-07-16 定，v1.2.0 落地）

6. **凭据绝不进仓库。** `.gitignore` 必须挡住 `*.cred` / `*.env` / `*_state.json`。
   只提交 `*.env.example`。

7. **法规定位（写进 SOP，别自己加戏）**：
   法规意义上的原始记录是 **FLEX2 机内数据库 + 审计追踪**；CSV 是副本，NAS 归档是副本的副本。
   本系统定位为**分析数据源 + 业务备份**，**不是** Part 11 原始记录保存系统。
   这个定位能显著降低验证等级。不要在代码或文档里暗示相反的意思。

8. **真库建表走 `cmc-schema-migrations`，本项目 `sql/` 只是本地测试镜像 —— 这是规矩，不能破。**
   将来 Stage 2 ETL 要往 `cmc_rd` 建表 / 改表，**权威 DDL 一律在独立仓库 `cmc-schema-migrations`**
   （Alembic 迁移，命令 `dbmig`）里加迁移，和 `rd-vicell-etl` / `rd-lucullus-etl` 完全一致。
   本项目里的 `sql/001_cmc_rd_flex2.sql`（若创建）**只是本地一次性测试用的镜像副本，不是权威建表脚本**；
   一旦改结构必须两处同步，且**以 `cmc-schema-migrations` 为准**。**绝不拿本项目的 sql 直接在生产库上跑。**

## 数据源（已定，不要再改）

| 数据源 | 定位 | 说明 |
|---|---|---|
| `Results/SampleResults{AID}<YYYY>-<Month>.csv` | **✅ 唯一主数据源** | 月度累积，整月持续追加 |
| `Results/QcResults{AID}<YYYY>-<Month>.csv` | ✅ 一并采集 | 同上 |
| `Database/Backup_<ts>/` | ⚠️ 每日归档（保险） | 每晚覆盖，只留一份，不抓就永久丢失 |
| `Results/SampleResults{AID}<YYYY-MM-DD_HHMMSS>.csv` | ✅ **日常自动归档**（已开 `--per-event`） | 两类：① 同事早期手动导的 311 个（历史留存，不再作解析依据）；② **2026-07-23 全量重新导出的 3 个文件 = 现在的数值主源**（7710 行，零错位，覆盖 100% 历史）。见 `docs/source-survey-flex2.md` §10 |
| `Report/*.pdf` | ❌ 忽略 | 人工导的报告 |

`{AID}` = Analyzer ID = `T281240040C`（出现在每个文件名里，是多机区分的唯一标识）

**月度文件是"活的"** —— 整月都在长。策略是**每次内容变化存一份带时间戳的快照**，
不是覆盖同一个文件。额外好处：历史行若被改写或消失（`last_data_rows` 变少），脚本会立刻告警。
这是很硬的数据完整性证据。

## 风格约定

- 中文注释，中英混排技术术语
- 变更控制：改动逻辑请递增脚本内 `SCRIPT_VERSION` 并更新 `CHANGELOG.md`
- Stage 1 只用标准库（无第三方依赖）；Stage 2 可用 pandas / psycopg
- 沿用既有 Biacore 备份脚本的语义：state JSON + Checksums 目录 + 机器名 tag
